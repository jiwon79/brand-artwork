# PBR 재질: roughness, specular, 환경광 강도, metalness

같은 모양과 기본색을 가진 물체도 빛을 반사하는 방식에 따라 플라스틱, 무광 도자기, 금속처럼 보인다. PBR(physically based rendering)은 표면과 빛의 성질을 이용해 이 차이를 계산한다.

네 값은 서로 다른 질문에 답한다.

| 파라미터 | 조절하는 것 | 반사된 창문을 보면 |
| --- | --- | --- |
| roughness | 반사가 퍼지는 정도 | 창문 윤곽이 선명한가, 흐릿하게 번지는가 |
| specular | 비금속 표면의 반사량 | 같은 흐림 정도에서 반사가 얼마나 강한가 |
| 환경광 강도(Environment intensity) | 환경에서 들어오는 빛의 세기 | 주변 공간이 표면을 얼마나 밝히고 비치는가 |
| metalness | 기본색이 확산광과 반사광에 배분되는 방식 | 색을 가진 표면에 흰 반사가 더해지는가, 반사 자체에 색이 실리는가 |

**roughness는 반사의 폭과 흐림, specular는 반사의 강도**를 조절한다. specular를 높여 반사가 잘 보이는 것과 roughness를 낮춰 반사 윤곽이 선명해지는 것은 다른 변화다.

## 비교 이미지의 조건과 읽는 순서

이미지는 실제 Three.js 0.163.0의 `MeshPhysicalMaterial`로 렌더링한 설명용 구다. 생성형 이미지가 아니다. 파라미터 이름 `specular`는 이 비교에서 `specularIntensity`, 환경광 강도(Environment intensity)는 코드의 `envMapIntensity`를 뜻한다. 다른 엔진의 같은 이름이 항상 같은 계산을 뜻하지는 않는다.

- 모든 그림에서 기본색, 형태, 카메라, 직접 조명은 같다.
- 밝은 창문과 천장, 어두운 벽을 표현한 동일한 환경 맵을 사용한다.
- IOR(굴절률)는 1.5, clearcoat(별도 코팅층)는 0이다.
- 각 그림에서는 제목에 적힌 파라미터만 바꾼다. 다른 재질 값은 그림 위에 표시했다.
- **윗줄 왼쪽부터 0, 0.2, 0.4, 아랫줄 왼쪽부터 0.6, 0.8, 1**이다. 각 구 아래에도 파라미터와 값을 표시했다.
- 계산된 빛에 ACES 톤 매핑과 화면 색 변환을 적용했다. 화면에서 보이는 밝기는 계산값에 정비례하지 않는다.

## 1. Roughness: 반사를 얼마나 퍼뜨릴까

![roughness를 0, 0.2, 0.4, 0.6, 0.8, 1로 바꾼 실제 구 렌더. 고정값은 위에, roughness와 값은 각 구 아래에 표시](../assets/pbr-roughness-comparison.png)

### 어디를 보면 되는가

`0`에서는 구 앞에 비친 창문과 오른쪽 밝은 띠의 윤곽이 잘 보인다. `0.2`에서는 가장자리가 풀리고, `0.4`에서는 넓은 빛 덩어리처럼 보인다. `0.6~1`에서는 창문의 모양을 구분하기 어려워지고 넓고 부드러운 밝기 변화가 남는다.

roughness가 높아졌다고 빛이 모두 사라지는 것은 아니다. 좁은 곳에 모이던 반사가 여러 방향으로 퍼지는 것이다. 반사량 자체를 줄이는 것과 구분해야 한다.

### 무엇을 계산하는가

표면을 아주 크게 확대하면 작은 면들이 서로 다른 방향을 향한다고 생각할 수 있다. 매끄러운 표면에서는 이 방향들이 비슷하고, 거친 표면에서는 다양하다. 렌더러는 실제로 작은 면을 전부 만들지 않고 **미세한 면 방향의 분포**로 이 효과를 계산한다. 이 방식이 미세면(microfacet) 모델이다.

| 기호 | 의미 |
| --- | --- |
| `r` | 입력 roughness. 단위 없는 0~1 값 |
| `α` | 미세면 방향 분포의 거칠기 매개변수 |
| `q` | 표면 방향과 빛을 카메라로 반사하는 데 필요한 미세면 방향의 일치도. 두 단위 방향 벡터의 내적을 0~1로 제한한 값 |
| `D` | 필요한 방향을 향한 미세면의 분포 밀도. 반사율이나 최종 화면 밝기가 아님 |

이 비교의 엔진은 GGX 분포를 사용한다. 입력 roughness를 제곱해 분포 매개변수를 만든다.

```text
α = r²
D = α² / { π × [q² × (α² − 1) + 1]² }
```

`q=1`은 방향이 완전히 일치하는 경우다. 이때 식은 `D=1/(π×α²)`가 된다. 작은 `α`에서는 정확히 일치하는 방향의 밀도가 매우 높다. 방향이 어긋난 곳의 밀도는 낮아져 좁고 강한 반사가 생긴다. 큰 `α`에서는 최고점이 낮아지고 주변 방향에도 반사가 분포한다.

예를 들어 입력 `r=0.2`에서는 `α=0.04`, `r=0.8`에서는 `α=0.64`다. 제곱을 사용하는 것은 사용자가 조절하는 roughness와 미세면 분포를 연결하는 재매개변수화이며, 화면 blur의 반경을 제곱한다는 뜻은 아니다.

### D를 구한 뒤 픽셀에 무엇을 그리는가

D는 그 픽셀의 정반사 성분을 계산할 때 곱하는 값이다. 흰 하이라이트는 흰 조명이 비금속 표면에서 반사된 결과다. 조명이 빨간색이면 반사도 빨간색이 될 수 있고, 금속에서는 재질의 기본색이 반사색에 영향을 준다.

이 비교에 사용한 Three.js의 일반적인 GGX 직접 조명 계산을 한 조명에 대해 쓰면 다음과 같다. 그림자와 거리 감쇠가 있다면 들어오는 조명 값에 반영한다고 생각하면 된다.

| 기호 | 의미 |
| --- | --- |
| `Lᵢ` | 들어오는 조명의 RGB 값. 색과 강도를 포함 |
| `c` | 빛을 받는 각도에 따른 계수. 표면이 빛을 정면으로 받으면 1, 옆으로 받으면 0에 가까움 |
| `F` | 각도에 따른 프레넬 반사율. RGB 값 |
| `V` | 미세면 사이의 가림과 빛·시선 각도를 반영하는 보정값. 단순한 0~1 반사율은 아님 |
| `D` | 앞에서 구한 미세면 방향의 분포 밀도. 1보다 클 수도 있음 |
| `L정반사` | 이 조명이 해당 픽셀에서 만드는 정반사 RGB 성분 |

```text
정반사 반응(BRDF) = D × V × F
L정반사 = Lᵢ × c × D × V × F
```

RGB의 각 채널에 같은 D가 곱해진다. D가 높으면 다른 조건이 같을 때 그 방향의 정반사 성분이 강해진다. 이 성분을 확산 반사, 다른 조명의 반사, 환경광 성분과 더하고, 마지막에 톤 매핑과 화면 색 변환을 거쳐 픽셀을 표시한다. [실제 BRDF와 직접 조명 계산](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/lights_physical_pars_fragment.glsl.js)

### F: 미세면에서 반사되는 비율

F는 프레넬 반사율이며, RGB 각 채널에 대해 계산한다. 재질의 기준 반사율 `F₀`에서 시작해 빛이 미세면을 스치는 각도가 될수록 반사율이 커진다. 이 문서의 비금속 예시는 IOR=1.5, specularIntensity=1이므로 `F₀=(0.04,0.04,0.04)`이다.

빛을 카메라로 반사하는 데 필요한 미세면 방향을 `H`라고 하자. H는 표면에서 광원을 향하는 방향과 카메라를 향하는 방향을 더한 뒤 길이를 1로 만든 방향이다. F에 사용하는 각도 `φ`는 **H와 카메라 방향 사이의 각도**다. 앞의 빛을 받는 각도 계수 c는 전체 표면의 법선과 광원 방향 사이의 각도를 사용한다.

이해하기 쉬운 Schlick 근사식은 다음과 같다. 여기서는 스치는 각도의 반사율을 1로 둔다.

```text
u = cos φ
F = F₀ + (1 − F₀) × (1 − u)⁵
```

| 미세면 기준 각도 φ | F₀=0.04일 때 F, 채널별 | 반사율 |
| --- | --- | --- |
| 0° | 0.04 | 약 4% |
| 60° | 0.07 | 약 7% |
| 80° | 0.410 | 약 41% |
| 90°에 가까워짐 | 1에 가까워짐 | 약 100%에 접근 |

이 표는 Schlick 식의 계산값이다. 실제 Three.js r163은 `(1−u)⁵`를 `2^[(-5.55473u−6.98316)u]`로 근사한다. 예를 들어 60°에서 약 0.0726이 된다. F가 커지면 조명 RGB에 곱해지는 반사 비율이 커진다. 최종 픽셀 밝기는 D, V, 입사광과 함께 결정된다. [F 계산 코드](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/common.glsl.js)

### V: 미세면의 가림과 각도를 함께 보정하는 값

미세면은 빛이 들어오는 길이나 카메라로 나가는 길을 다른 미세면에 가릴 수 있다. V는 이 가림 효과와 BRDF의 각도 보정을 함께 계산한다. 가림만 나타내는 계수 `G`를 사용하면 관계는 다음과 같다.

```text
a = max(표면 법선 · 광원 방향, 0)       ← 앞의 c와 같은 값
b = max(표면 법선 · 카메라 방향, 0)
V = G / (4 × a × b)                    ← a, b가 양수인 경우
```

G는 0~1의 가림 계수다. V에는 `4ab`로 나누는 보정까지 포함되므로 1보다 큰 값도 나올 수 있다. Three.js의 GGX Smith 상관 가림 모델은 G를 따로 구하는 대신 V를 다음 식으로 직접 계산한다.

```text
α = 계산용 roughness²
t = α²
g₁ = a × √[t + (1 − t) × b²]
g₂ = b × √[t + (1 − t) × a²]
V = 0.5 / max(g₁ + g₂, 0.000001)
```

| 계산용 roughness | a | b | V | 대응하는 G=4abV |
| --- | --- | --- | --- | --- |
| 0.2 | 1 | 1 | 0.25 | 1 |
| 0.8 | 1 | 1 | 0.25 | 1 |
| 0.2 | 0.5 | 0.5 | 약 0.998 | 약 0.998 |
| 0.8 | 0.5 | 0.5 | 약 0.670 | 약 0.670 |
| 0.8 | 0.1 | 0.1 | 약 3.878 | 약 0.155 |

광원과 카메라가 모두 표면 정면에 있으면 `a=b=1`이고 V는 0.25다. 둘 다 비스듬한 `a=b=0.5`에서는 거칠기가 커질수록 가림 효과가 커져 V가 줄어드는 예를 볼 수 있다. 마지막 행은 작은 `4ab`로 나누어 V가 1을 넘는 경우다. 이때 가림 계수 G는 약 0.155이며, 반사량은 `Lᵢ × a × D × V × F` 전체로 계산한다. [V 계산 코드](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/lights_physical_pars_fragment.glsl.js)

### 계산한 F, V, D를 RGB에 적용하는 예

곱셈만 확인하기 위해 `Lᵢ=(1,1,1)`, `c=0.8`, `F=(0.04,0.04,0.04)`, `V=0.4`로 고정해 보자.

| D | 계산 | 더해지는 정반사 RGB |
| --- | --- | --- |
| 2 | `1 × 0.8 × 2 × 0.4 × 0.04` | `(0.0256, 0.0256, 0.0256)` |
| 10 | `1 × 0.8 × 10 × 0.4 × 0.04` | `(0.128, 0.128, 0.128)` |

예를 들어 다른 조명 성분의 합이 `(0.1,0.3,0.5)`라면, 두 번째 정반사를 더한 결과는 `(0.228,0.428,0.628)`이다. 흰 성분이 더해져 밝아지고 색이 옅어진다. 이것은 화면 변환 전의 선형 RGB 계산 예시이며, 위 비교 사진에서 측정한 값은 아니다. 실제로 roughness를 바꾸면 D뿐 아니라 V와 환경 반사 계산도 달라진다.

### 그렇다면 왜 하이라이트가 주변으로 퍼져 보이는가

구에서는 위치마다 표면 방향이 다르므로 각 픽셀에서 계산한 D도 달라진다. 위 roughness 사진의 좁은 밝은 반사 중심을 A, 그 바깥쪽을 B라고 생각해 보자.

| 위치 | roughness가 낮을 때 | roughness가 높을 때 |
| --- | --- | --- |
| A: 반사에 필요한 방향과 잘 맞는 곳 | D가 매우 높아 강한 반사가 생김 | D의 최고점이 낮아져 반사가 약해질 수 있음 |
| B: 그 방향에서 조금 어긋난 곳 | D가 낮아 반사가 약함 | 분포가 넓어져 D가 커질 수 있음 |

A와 B에서 각각 표면 방향, 광원 방향, 카메라 방향으로 c, D, V, F를 구하고 조명 RGB에 곱한다. roughness가 커지면 미세면 방향 분포가 넓어져, 반사 중심에서 조금 어긋난 위치에도 반사 성분이 나타날 수 있다. 곡면에서는 이 방향 차이가 화면상의 위치 차이로 나타나므로 넓은 하이라이트가 보인다.

표면 방향이 모두 같은 평면에 동일한 방향광이 들어오고 시선 방향도 같다면, 각 픽셀의 D도 같다.

환경 반사도 roughness에 따라 더 넓은 방향의 빛을 평균한 환경 맵을 조회한다. 환경에서 들어오는 여러 방향의 빛이 반사에 기여하므로 창문 반사의 경계도 부드러워진다. [환경 반사 조회](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/envmap_physical_pars_fragment.glsl.js)

> **roughness에는 계산용 최소값이 있다:** 입력 roughness를 정확히 0으로 식에 넣으면 `α=0`이 된다. 반사 방향이 정확히 일치하는 `q=1`에서는 D의 분자와 분모가 모두 0이 되어 `0/0`으로 정의되지 않는다. 방향이 어긋난 `q<1`에서 D가 0인 것만 보고 전체 반사가 사라진다고 해석하면 안 된다. 완벽한 거울은 정확한 반사 방향에 빛이 집중되는 극한이다.
>
> **이 문제를 피하기 위해 계산에는 0보다 큰 roughness를 사용한다.** 이 비교의 Three.js r163은 환경 맵 해상도를 고려한 **최소값 0.0525**를 적용하고, 표면 방향의 화면상 변화량으로 추가 보정한다. 따라서 입력이 0이어도 계산용 roughness는 0이 아니며, 위 식의 `0/0` 문제를 피한다. 0.0525는 이 엔진의 구현값이지 모든 PBR 렌더러의 공통 상수는 아니다. 그림의 입력 0은 수학적으로 완벽한 거울이 아니다. roughness는 구의 실제 형상에 돌기를 추가하는 값도 아니다. [최소값 적용 코드](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/lights_physical_fragment.glsl.js)

## 2. Specular: 같은 반사를 얼마나 강하게 보이게 할까

![specularIntensity를 0부터 1까지 0.2 간격으로 바꾼 실제 비금속 구 렌더](../assets/pbr-specular-comparison.png)

### 어디를 보면 되는가

구 위쪽의 밝은 점과 오른쪽 반사 띠를 비교한다. `0`에서는 정반사 성분이 없어지고, 값을 높일수록 밝은 점과 환경 반사가 강해진다. **roughness는 모든 구에서 0.25로 같으므로 반사 분포의 폭을 바꾸는 비교가 아니다.**

반사가 약할 때 안 보이던 영역이 값이 커지면 보일 수 있다. 이 때문에 반사 영역의 크기도 달라진 것처럼 느껴질 수 있지만, 거칠기 자체는 그대로다.

### 무엇을 계산하는가

빛의 일부는 표면에서 바로 반사되고, 나머지는 내부로 들어가거나 흡수된다. 비금속의 기준 반사율은 굴절률 차이로 결정된다. 여기서는 흰 반사색을 사용하며 다음 기호를 쓴다.

| 기호 | 의미 |
| --- | --- |
| `s` | specularIntensity. 단위 없는 0~1 값 |
| `n` | 표면 재질의 IOR. 주변 공기의 굴절률을 1로 가정 |
| `F₀` | 정면 입사에서의 기준 반사율 |

```text
F₀ = s × [(n − 1) / (n + 1)]²
```

굴절률이 같은 두 매질 사이에서는 `n−1=0`이므로 이 반사가 사라진다. 차이가 커질수록 반사가 증가한다. `s`는 그 기준 반사량을 조절하는 배수다.

이번 비교의 `n=1.5`를 넣으면 다음과 같다.

```text
[(1.5 − 1) / (1.5 + 1)]² = (0.5 / 2.5)² = 0.04
F₀ = 0.04 × s
```

| specular | 0 | 0.2 | 0.4 | 0.6 | 0.8 | 1 |
| --- | --- | --- | --- | --- | --- | --- |
| 기준 반사율 | 0% | 0.8% | 1.6% | 2.4% | 3.2% | 4% |

**specular 1은 100% 반사를 뜻하지 않는다.** 여기서는 IOR 1.5의 기준 반사율 4%를 그대로 사용한다는 뜻이다. 이 수치는 기준 반사율이지, 구의 모든 픽셀이나 최종 화면 밝기 비율이 아니다.

카메라와 빛의 각도에 따른 프레넬 변화, roughness 분포, 미세면 사이의 가림도 함께 계산한다. 따라서 화면의 반사는 이 표 하나로 결정되지 않는다. [기준 반사색과 specular 계산](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/lights_physical_fragment.glsl.js)

> **적용 범위:** 이 비교의 specularIntensity는 비금속 반사량을 조절한다. metalness가 1인 금속에서는 이 값의 영향이 사라진다. 별도 clearcoat가 있다면 specular를 0으로 해도 코팅층 반사가 남을 수 있다.

## 3. 환경광 강도(Environment intensity): 주변에서 들어오는 빛이 얼마나 강할까

![envMapIntensity를 0부터 1까지 0.2 간격으로 바꾼 실제 구 렌더. 직접 조명은 고정](../assets/pbr-environment-comparison.png)

### 어디를 보면 되는가

`0`에서는 구의 아래쪽이 매우 어둡지만 위쪽의 밝은 점은 남아 있다. 환경광을 꺼도 직접 조명은 그대로 있기 때문이다. 값을 높이면 어두운 면이 밝아지고, 주변의 창문과 밝은 공간이 표면에 더 강하게 영향을 준다.

이 값은 창문 반사만 조절하지 않는다. **환경이 표면 전체를 부드럽게 밝히는 효과도 함께 조절**한다.

### 무엇을 계산하는가

환경 맵은 물체를 둘러싼 공간에서 들어오는 빛을 방향별로 저장한다. 반사 방향에서는 창문과 벽의 빛을 읽고, 확산광 계산에서는 표면이 향한 쪽의 넓은 환경빛을 사용한다.

`e`는 환경광 강도, `E_diffuse`는 환경 확산광 기여분, `E_specular`는 환경 정반사 기여분이다. 모두 화면 색 변환 전의 선형 빛 계산을 기준으로 한다.

```text
환경 기여분 = e × (E_diffuse + E_specular)
전체 빛 = 직접 조명의 기여분 + 환경 기여분
```

`e=0`이면 환경 기여분은 0, `e=0.4`이면 기준의 0.4배, `e=1`이면 기준 세기다. 고정된 표면에서 계산된 환경 기여가 0.2라면 각각 0, 0.08, 0.2가 된다.

이 식은 환경빛을 읽고 재질 반응을 계산한 결과를 묶어 보여주는 요약이다. 실제 구현은 환경 확산광과 반사용 빛을 조회할 때 각각 `envMapIntensity`를 곱한다. [환경광 강도 구현](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/envmap_physical_pars_fragment.glsl.js)

> **specular와의 차이:** specular는 재질의 반사 성질이라 직접 조명과 환경 반사에 영향을 준다. 환경광 강도는 환경빛의 입력 세기라 직접 조명은 그대로 둔다. 이 비교에서는 재질에 환경 맵을 직접 연결했다. scene의 환경만 사용하는 구성에서는 엔진 버전에 따라 scene의 환경 강도 설정을 확인해야 한다.

## 4. Metalness: 기본색을 어느 빛에 실을까

![metalness를 0부터 1까지 0.2 간격으로 바꾼 실제 구 렌더](../assets/pbr-metalness-comparison.png)

### 어디를 보면 되는가

`0`에서는 파란 기본색이 넓게 퍼진 표면 위에 밝은 반사가 더해진다. `1`에서는 어두운 벽을 비추는 곳이 짙어지고, 밝은 창문을 비추는 곳이 강하게 드러난다. 중간값에서는 두 성질이 섞인다.

**금속은 항상 밝은 물체가 아니다.** 주변에서 반사할 빛이 적으면 어둡게 보인다. 금속에서도 roughness를 높이면 넓고 흐릿한 반사가 생기므로, 금속 여부와 매끈함은 별개의 속성이다.

### 무엇을 계산하는가

비금속은 내부에서 퍼져 나오는 빛에 기본색이 나타나며, 표면 정반사는 대체로 조명의 색을 따른다. 금속은 일반적인 확산광 성분을 없애고 기본색을 반사 성분에 사용한다. 금속의 자유 전자가 빛에 반응하는 성질을 metallic-roughness 모델에서 이렇게 요약한다.

| 기호 | 의미 |
| --- | --- |
| `C` | 기본색의 선형 RGB 값. 화면에 적는 sRGB 색상 숫자와 구분 |
| `m` | metalness. 단위 없는 0~1 값 |
| `s` | 비금속에 사용하는 specularIntensity |
| `F₀` | 정면 기준의 반사색. RGB 각 채널에 대해 계산 |

IOR 1.5, 흰 반사색을 가정하면 다음과 같다.

```text
확산색 = C × (1 − m)
F₀ = (0.04 × s) × (1 − m) + C × m
```

`1−m`과 `m`은 비금속과 금속의 비중이다. 합이 1이므로 중간값에서 두 성질을 선형으로 섞는다. `m=1`이면 확산색은 0이고, 반사색에는 `C`만 남는다. 그래서 금속에서는 `s`의 영향도 사라진다.

숫자 예제로 기본색의 한 채널이 `C=0.5`, `s=1`이라고 하자. 이는 위 이미지의 실제 색상값과 별개인 계산 예다.

| metalness | 확산색 계수 | 기준 반사색 계수 |
| --- | --- | --- |
| 0 | `0.5 × 1 = 0.5` | `0.04 × 1 + 0.5 × 0 = 0.04` |
| 0.5 | `0.5 × 0.5 = 0.25` | `0.04 × 0.5 + 0.5 × 0.5 = 0.27` |
| 1 | `0.5 × 0 = 0` | `0.04 × 0 + 0.5 × 1 = 0.5` |

확산색과 반사색은 이후 서로 다른 조명 계산에 사용되는 계수다. 두 숫자를 더하면 곧바로 최종 화면 밝기가 되는 것은 아니다. [금속성에 따른 색 배분](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/lights_physical_fragment.glsl.js)

> **중간값의 의미:** 균일한 재질은 보통 비금속 0 또는 금속 1로 구분한다. 중간값은 경계의 혼합, 텍스처 필터링, 예술적 조절에 쓸 수 있지만, 실제 물질이 정확히 ‘반쯤 금속’이라는 의미는 아니다. 페인트·산화층·코팅이 덮인 금속은 표면층을 고려해야 한다.

## 5. 네 값이 최종 픽셀에 연결되는 순서

각 표면 픽셀마다 GPU는 재질 값, 표면 방향, 카메라 방향, 빛의 방향과 세기를 사용한다. 입력값은 재질에 저장하고, 각도에 따른 반응은 픽셀마다 계산한다. 환경 맵은 미리 준비한 텍스처다.

1. **metalness**로 확산색과 기준 반사색을 정한다.
2. **specular**와 IOR로 비금속의 기준 반사량을 정한다.
3. **roughness**로 반사 방향의 분포와 환경 맵의 평균 범위를 정한다.
4. 직접 조명과 환경광의 재질 반응을 계산한다. **환경광 강도**는 환경빛의 세기를 배율로 조절한다.
5. 빛을 합산한 뒤 노출·톤 매핑·화면 색 변환을 거쳐 픽셀 색을 출력한다.

이 목록은 이해를 위한 의존 관계이며, 특정 엔진의 shader 실행문 순서를 그대로 나열한 것은 아니다.

## 6. 헷갈릴 때의 구분과 조절 순서

| 원하는 변화 | 먼저 조절할 값 | 이유 |
| --- | --- | --- |
| 비친 창문의 윤곽을 더 선명하게 | roughness 감소 | 반사되는 방향의 퍼짐을 줄임 |
| 윤곽의 흐림은 유지하면서 비금속 반사를 더 강하게 | specular 증가 | 반사량을 늘림 |
| 주변에서 비추는 빛과 어두운 면의 밝기를 함께 늘리기 | 환경광 강도 증가 | 환경빛의 입력을 늘림 |
| 기본색이 금속의 반사색으로 나타나게 | metalness 증가 | 확산색을 줄이고 반사색에 기본색을 사용 |

플라스틱이나 도자기를 조절한다면 metalness를 0으로 두고 roughness로 퍼짐을 정한 다음 specular로 반사량을 맞춘다. 환경 세기는 같은 재질이 어떤 공간에 놓여 있는지를 맞추는 데 사용한다. 수치는 위 비교 장면의 설정이며 실제 상품의 재질 측정값이나 작품별 추천 기본값은 아니다.
