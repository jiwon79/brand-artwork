# PMREM: roughness에 맞는 환경빛을 미리 계산하기

**PMREM은 환경 맵의 빛을 미리 평균해서, 거친 표면의 환경 반사를 빠르게 계산하는 데이터다.**
전체 이름은 Prefiltered, Mipmapped Radiance Environment Map이다.
입력은 방향별 빛의 RGB다.
출력은 서로 다른 필터 범위로 계산한 환경 맵이다.

## 1. 결과를 이미지로 보기

![PMREM 환경 맵을 사용한 실제 roughness 비교. 고정값은 위에, 변경값은 각 구 아래에 표시](../assets/pbr-roughness-comparison.png)

roughness가 낮으면 창문 반사의 윤곽이 선명하다.
roughness가 높으면 창문 반사가 넓어지고 흐려진다.
PMREM은 이 환경 반사에 필요한 빛의 평균값을 제공한다.

이 이미지는 Three.js r163의 PMREM을 사용한 실제 렌더다.
직접 조명의 하이라이트도 포함한다.
따라서 이미지 전체는 PMREM과 재질의 직접 조명 계산을 함께 반영한다.

## 2. PMREM이 필요한 이유

**거친 표면의 한 픽셀에는 여러 방향의 환경빛이 기여한다.**
렌더러는 각 방향의 빛과 표면의 반사 반응을 합산해야 한다.
이 합산을 모든 픽셀에서 매 프레임 계산하면 조회 횟수가 많아진다.

PMREM은 환경 맵이 준비될 때 이 계산의 일부를 미리 수행한다.
렌더링 중에는 준비한 텍스처를 조회한다.
roughness가 바뀌면 해당 roughness에 맞는 필터 수준을 조회한다.
환경 맵이 같으면 여러 물체가 같은 PMREM을 사용할 수 있다.

## 3. 입력: 환경 맵의 실제 데이터

환경 맵은 방향별로 들어오는 빛의 RGB를 저장한다.
파노라마 이미지나 큐브 맵으로 표현할 수 있다.
큐브 맵은 주변 방향을 여섯 면에 나누어 저장한다.
텍스처의 한 데이터 위치를 texel이라고 한다.

| 데이터 | 의미 |
| --- | --- |
| 방향에 대응하는 texel 위치 | 어느 방향에서 들어오는 빛인가 |
| texel의 RGB | 그 방향의 빛이 어떤 색이며 얼마나 강한가 |
| 선형 RGB | 빛을 합산하고 평균할 때 사용하는 색 표현 |
| HDR | 1보다 큰 밝기도 저장할 수 있는 범위 |

다음 값은 설명용 예시다.
실제 비교 이미지에서 측정한 값은 아니다.

| 환경 방향 | 공간 | 선형 RGB 예시 |
| --- | --- | --- |
| 창문 방향 | 밝은 창문 | `(8.0, 7.5, 6.0)` |
| 위쪽 | 천장 | `(0.8, 0.8, 0.7)` |
| 벽 방향 | 어두운 벽 | `(0.03, 0.03, 0.04)` |

HDR의 8.0은 화면에서 표시할 흰색 1.0보다 강한 빛을 나타낼 수 있다.
렌더러는 이 빛을 재질 계산에 사용한다.
화면 표시에는 나중에 톤 매핑을 적용한다.

## 4. 미리 계산: 여러 방향의 빛을 평균하기

**PMREM은 각 출력 방향에 대해 주변 입사 방향의 RGB를 가중 평균한다.**
필터 범위가 좁으면 원본의 밝은 창문을 선명하게 유지한다.
필터 범위가 넓으면 창문과 주변 벽의 빛이 함께 평균된다.

다음 식은 가중 평균의 원리를 설명한다.
특정 엔진의 shader 구현을 그대로 옮긴 식은 아니다.

| 기호 | 의미 |
| --- | --- |
| `d` | 출력 환경 맵을 조회할 방향. 길이는 1 |
| `r` | 필터 수준에 대응하는 roughness |
| `ωⱼ` | 평균에 사용할 입사 방향 표본. 길이는 1 |
| `L(ωⱼ)` | 해당 입사 방향에서 읽은 선형 RGB |
| `wⱼ(d,r)` | 방향과 필터 수준에 따른 표본 가중치 |
| `P(d,r)` | 미리 평균한 환경빛의 선형 RGB |

```text
P(d,r) = Σ[wⱼ(d,r) × L(ωⱼ)] / Σ[wⱼ(d,r)]
```

Σ는 표본들의 값을 더한다.
RGB 각 채널에 같은 가중치를 적용한다.
가중치 합으로 나누어 평균의 크기를 맞춘다.
표본 위치와 가중치는 필터 방식에 따라 달라진다.

### 숫자로 확인하기

창문의 한 채널을 8.0으로 가정한다.
주변 벽의 같은 채널을 0.1로 가정한다.

| 설명용 가중치 | 평균 계산 | 결과 |
| --- | --- | --- |
| 창문 0.9, 벽 0.1 | `8.0×0.9 + 0.1×0.1` | 7.21 |
| 창문 0.3, 벽 0.7 | `8.0×0.3 + 0.1×0.7` | 2.47 |

넓은 필터에서는 밝은 중심에 어두운 주변 방향이 더 많이 기여할 수 있다.
반대로 어두운 주변 방향의 평균에는 밝은 창문이 기여할 수 있다.
그 결과 밝기 변화가 넓고 부드러워진다.
이 예시의 가중치는 계산 설명용이다.
roughness에서 위 가중치로 직접 변환하는 규칙은 아니다.

## 5. 출력: 여러 필터 수준을 가진 텍스처

**PMREM 출력에는 여러 수준으로 평균한 환경빛이 들어 있다.**
필터 수준은 roughness별 조회에 사용한다.

| 수준 | 담긴 데이터 | 반사 결과 |
| --- | --- | --- |
| 좁은 필터 | 좁은 방향 범위의 환경빛 | 선명한 반사 |
| 중간 필터 | 더 넓은 방향 범위의 환경빛 | 부드러운 반사 |
| 넓은 필터 | 넓은 방향 범위의 환경빛 | 넓고 흐린 반사 |

일반 mipmap은 텍스처의 축소 수준을 제공한다.
PMREM은 재질의 반사에 맞는 필터 수준을 제공한다.
따라서 이미지 크기를 줄이는 것만으로 같은 결과를 얻지는 못한다.

Three.js r163은 여러 큐브 면과 필터 수준을 CubeUV 텍스처에 배치한다.
CubeUV는 큐브 면과 필터 수준을 한 2D 텍스처에 저장하는 배치 방식이다.
이 구현은 일정 해상도까지 크기를 줄인다.
그 뒤에는 같은 최소 해상도에서 더 강한 필터 수준을 추가한다.
[r163 PMREM 출력과 필터 구현](https://github.com/mrdoob/three.js/blob/r163/src/extras/PMREMGenerator.js)

## 6. 렌더링: 방향과 roughness로 조회하기

**렌더링 중에는 표면의 반사 방향과 roughness로 PMREM 값을 조회한다.**
다음 순서로 환경 정반사를 계산한다.

1. 표면 법선과 카메라 방향을 구한다.
2. 이 방향으로 환경 반사 조회 방향을 구한다.
3. roughness에 맞는 필터 수준을 구한다.
4. 해당 방향과 필터 수준의 RGB를 읽는다.
5. 인접한 필터 수준 사이를 보간한다.
6. 환경광 강도를 적용한다.
7. 재질의 환경 반사 반응을 적용한다.

```text
환경빛 RGB = PMREM 조회(반사 조회 방향, roughness)
환경빛 입력 = 환경광 강도 × 환경빛 RGB
환경 정반사 RGB = 환경빛 입력에 재질의 환경 반사 반응 적용
```

조회한 PMREM 값은 들어오는 빛의 평균값이다.
최종 물체 색에는 재질의 기준 반사색과 각도 반응도 필요하다.
roughness는 평균 범위에 영향을 준다.
specular와 metalness는 재질의 반사 반응에 영향을 준다.

실시간 렌더러는 환경빛의 방향 합산과 재질 반응을 분리해서 근사할 수 있다.
이 방식을 split-sum 근사라고 한다.
엔진에 따라 반사 반응을 LUT나 수식 근사로 구한다.
Three.js r163은 환경 BRDF의 수식 근사와 다중 산란 보정을 사용한다.
반사 조회 방향에도 roughness에 따른 보정을 적용한다.
[r163 환경 조회](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/envmap_physical_pars_fragment.glsl.js), [r163 환경 BRDF](https://github.com/mrdoob/three.js/blob/r163/src/renderers/shaders/ShaderChunk/lights_physical_pars_fragment.glsl.js)

## 7. 직접 조명 및 확산 반사와의 관계

직접 조명은 각 광원의 방향과 RGB를 사용한다.
일반적인 GGX 직접 정반사는 a, D, F, V로 계산한다.
PMREM은 환경 맵에서 오는 빛의 계산에 사용한다.

환경 확산 반사는 표면 앞쪽의 넓은 환경빛을 합산한다.
이 비교의 Three.js 구현은 넓게 필터한 PMREM 값도 환경 확산 반사에 사용한다.
정반사와 확산 반사는 서로 다른 재질 반응을 적용한다.
[확산 반사와 정반사의 전체 계산](./pbr-material-parameters.md)

## 8. Three.js에서 연결하기

파노라마 텍스처를 준비한 뒤 다음과 같이 변환한다.
HDR 입력은 로더에 맞는 선형 색 공간 설정을 사용한다.

```js
const generator = new THREE.PMREMGenerator(renderer);
const environment = generator.fromEquirectangular(sourceTexture);

material.envMap = environment.texture;
material.envMapIntensity = 0.8;

generator.dispose();
```

`sourceTexture`는 원본 환경 맵이다.
`environment.texture`는 변환한 PMREM 텍스처다.
`generator.dispose()`는 생성기의 내부 자원을 해제한다.
결과 텍스처를 더 이상 사용하지 않으면 `environment.dispose()`도 호출한다.
환경 맵을 갱신하면 PMREM도 다시 계산해야 한다.

## 9. 한계와 구현 차이

PMREM은 유한한 해상도와 필터 수준을 사용한다.
아주 작은 광원이나 날카로운 반사는 원본과 차이가 날 수 있다.
한 환경 맵은 보통 한 위치에서 본 주변 빛을 나타낸다.
물체의 이동에 따른 시차나 가까운 물체의 가림에는 추가 처리가 필요하다.

PMREM의 구체적인 필터 방식은 엔진과 버전에 따라 달라진다.
이 문서의 비교 렌더는 Three.js r163을 사용한다.
r163은 구면 방향의 blur 패스로 반사 분포를 근사한다.
최신 구현의 샘플링 설명을 r163에 그대로 적용하지 않는다.
[최신 Three.js API 참고](https://threejs.org/docs/pages/PMREMGenerator.html)
