# Clouds

`/clouds/`는 카메라와 태양을 조작하며 절차적 3D 구름을 살펴보는 작품이다. [Clouds in Motion](https://clouds-in-motion.pages.dev/)의 형태·조명·조작을 참고하되, 코드는 독립적으로 작성했다. 원본의 Gaussian splat 렌더러 대신 사전 생성한 3D 밀도 텍스처와 GPU ray marching을 사용한다. 형태는 고정되고 카메라, 조명, 번개가 변한다.

## 입력

- `script.ts`: 구름 프리셋, seed, 태양 높이·방향, 밀도, 노출, 화질, 번개, PNG 저장.
- `renderer.ts`: 마우스·터치·방향키 회전, 휠·핀치 확대, Shift 드래그 이동, R 초기화, 자동 궤도 회전.
- 카메라와 밀도 변경은 즉시 움직임 상태를 시작한다. 마지막 조작 후 180ms가 지나면 정지 품질로 전환한다.
- 좌표는 임의의 world unit이며 밀도 영역은 `volume.ts`의 `MIN`, `EXTENT`로 정의된다. 화면 크기는 CSS pixel, 실제 렌더링 크기는 device pixel이다.

## 중간 상태: 밀도와 그림자

### 사전 생성한 기본 프리셋

`pnpm generate:clouds`는 `scripts/generate-clouds.mjs`에서 `volume.ts`를 실행하여 다음 데이터를 만든다.

1. 큰 타원체 → 작은 돌출부 → 작은 봉오리로 구름 외곽을 구성한다.
2. 인접 타원체만 숫자 index의 공간 bin으로 조회하여 밀도 격자를 채운다. 반지름의 역수를 미리 저장하고, 이미 더 높은 밀도 영역에 가려진 후보의 제곱근 계산을 생략한다. 경계의 3D 노이즈는 생성 시 계산하며 깊은 내부에서는 생략한다.
3. `256 × 192 × 192`개의 밀도 값을 8bit로 저장한다.
4. 기본 태양 방향의 투과율을 `128 × 96 × 80` 격자에 계산한다.
5. 형식 식별자·seed·배열 길이와 두 배열을 gzip으로 압축한다.

`assets/cumulus.cloud`, `tower.cloud`, `bank.cloud`는 생성기와 함께 관리하는 런타임 에셋이다. 방문자의 기기에서는 다운로드와 압축 해제, GPU 업로드만 수행한다. 브라우저 메모리에 읽기 promise를 캐시하여 같은 프리셋으로 돌아갈 때 재다운로드하지 않는다. Evening light는 Cumulus, Thunderstorm은 Tower의 형태를 공유한다.

### 새 랜덤 구름

`cloud-worker.ts`는 같은 밀도 생성기를 Worker에서 실행한다. 이전 구름은 화면에 남고 새 밀도가 완성되면 교체한다. 연속 요청 시 이전 Worker를 종료하고 요청 번호로 오래된 결과를 무시한다. 랜덤 형태의 그림자는 GPU에서 새로 만든다.

### 태양 변경

그림자는 각 격자 위치에서 태양 방향으로 밀도를 112번 조회하여 계산한 투과율이다. 간격은 0.3 world unit이며 밀도의 기본 소광 계수는 3.2이다. 이 계수가 너무 작으면 빛이 경계 안쪽까지 퍼져 외곽과 굴곡이 흐릿해진다. 누적 광학 두께가 8을 넘으면 중단한다. CPU 사전 생성과 GPU 생성의 조회·간격·기본 태양은 같다.

- 조작 중: `32 × 24 × 20` 격자를 최대 약 75ms 간격으로 갱신한다.
- 정지 후: 큰 격자의 80개 층을 frame당 4개씩 scratch texture에 채운다. 모든 층이 완성된 뒤 한 번에 교체하여 미완성 그림자를 표시하지 않는다.
- 카메라만 바뀌면 그림자는 그대로 사용한다.
- 밀도 슬라이더는 저장된 투과율을 밀도 배율만큼 거듭제곱하므로 그림자를 다시 만들 필요가 없다.

## 렌더 패스

| 순서 | 입력 → 출력 | 계산 시점 |
| --- | --- | --- |
| 그림자 | 밀도 + 태양 → 3D 투과율 | 구름 또는 태양 변경 시 |
| 구름 | 카메라 광선 + 밀도 + 그림자 → HDR 화면 | 조작 중 또는 샘플 누적 중 |
| 평균 | 현재 HDR 샘플 + 이전 평균 → 새 평균 | 새 샘플을 그릴 때 |
| 카메라 | 평균 + 노출·빛 번짐 → 최종 Canvas | 화면 갱신 시 |

`shaders.ts`의 구름 패스는 광선과 밀도 영역의 진입·이탈 거리를 구한 뒤 그 구간을 일정 간격으로 조회한다. 각 위치의 밀도와 이동 간격의 곱에 사용자 밀도 배율을 적용하면 광학 두께가 된다. 두께가 클수록 `exp(-두께)`가 작아져 뒤쪽 빛을 덜 통과시킨다. 남은 투과율이 0.008보다 작아지면 뒤쪽 계산을 종료한다.

픽셀마다 첫 밀도 경계 위치를 보관하고, 그 위치 주변 여섯 방향의 밀도 차이로 경계 normal을 한 번 복원한다. 작은 굴곡의 방향에 맞춰 밝기를 보정한다. 광선의 모든 위치에서 normal을 구하지 않으므로 비용을 제한한다.

조명은 직접광, 여러 감쇠율을 합친 다중 산란 근사, 경계 근처의 국소 밀도 차이, 하늘 간접광을 합친다. 태양 높이는 하늘과 햇빛의 색도 바꾼다. 번개는 구름 내부 광원과 꺾인 3D 선분에 가까운 영역의 발광으로 표현한다.

## 출력과 성능 정책

`performance.ts`는 다음 세 구간을 정의한다.

| 상태 | 내부 해상도 | 광선 조회 | 평균 샘플 |
| --- | --- | --- | --- |
| 조작 중 | 출력 가로·세로의 35–60% | 128 | 1 |
| 기본 화질 정지 | 출력의 100% | 192 | 24 |
| 정밀 화질 정지 | 출력의 100% | 256 | 48 |

출력은 DPR을 최대 2, 긴 축을 최대 2880px, 총 픽셀 수를 약 400만으로 제한한다. 기본 화질도 정지하면 출력의 전체 해상도로 계산하여 Retina 화면에서 별도의 75% 축소가 누적되지 않도록 한다. 내부 이미지는 선형 필터로 확대한다. GPU timer query가 지원되면 완료된 query만 비동기로 읽고 조작 해상도를 5%씩 조정한다. 동기 readback이나 GPU 완료 대기는 하지 않는다.

카메라·밀도·태양·형태·화질 변경은 샘플 평균을 초기화한다. 노출과 빛 번짐은 기존 평균에 후처리만 적용한다. 조작 중에는 광선 조회 위치의 무작위 흔들림을 줄여 한 샘플 화면의 거친 입자를 억제한다. 정지 중에는 전체 흔들림과 평균으로 경계 aliasing을 줄인다. 샘플이 완성되면 RAF 반복을 중단한다. 백그라운드에서는 RAF와 예약된 번개를 중지한다. reduced motion에서는 자동 번개가 꺼지고 사용자 선택으로 궤도 회전을 켤 수 있다.

화면에는 실제 그린 frame의 FPS, GPU 작업 시간, 이미지 크기, 누적 샘플 수를 표시한다. GPU query를 지원하지 않으면 시간은 `—`로 표시한다. WebGL 2가 없거나 context가 손실되면 재로드 안내를 표시한다. float render target을 지원하지 않으면 8bit target을 사용하며 강한 빛의 표현 범위가 좁아진다.

PNG 저장은 현재 완성된 Canvas를 저장한다. 설정 패널과 글자는 포함하지 않는다. 고화질 파일이 필요하면 정지 화면 화질을 고화질로 바꾼 뒤 완성 상태에서 저장한다.

## 검증

- `pnpm test pages/clouds`: seed 재현성, 밀도 조회의 half-texel 보간과 영역 밖 처리, 그림자 투과율, 배포 데이터 길이·손상 검출, 화면 크기 제한과 품질 정책.
- `pnpm typecheck`: Worker와 렌더러를 포함한 TypeScript 검사.
- `pnpm build`: 모든 작품과 Worker·압축 에셋의 배포 번들 생성.
- 기존 Chrome에서 초기 로딩, 회전·확대, 태양·밀도 변경, 프리셋 전환, 연속 랜덤 생성, 모바일 레이아웃, PNG 저장, 콘솔 오류를 확인한다.
- 런타임 측정값은 Canvas의 `data-first-frame-ms`, `data-settle-ms`, `data-generation-ms`, `data-gpu-ms`, `data-shadow-builds`, `data-draws`에서 확인한다. GPU 시간과 FPS는 기기·화면 크기·프리셋에 따라 달라진다.

## 한계

원본 가우시안의 해석적 적분을 구현한 것은 아니다. 밀도와 그림자는 격자 해상도 및 광선 샘플 수에 따른 근사를 사용하므로 확대하면 작은 돌출부가 손실되고, 움직임 중에는 노이즈가 보일 수 있다. 다중 산란과 번개 역시 물리적으로 보정한 기상 모델이 아니다. 약한 GPU에서는 해상도를 줄여 반응성을 유지하며 모든 기기에서 60fps를 보장하지 않는다.
