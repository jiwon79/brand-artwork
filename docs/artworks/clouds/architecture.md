# Clouds

`/clouds/`는 카메라와 태양을 조작하며 3D 구름을 살펴보는 작품이다. [Clouds in Motion](https://clouds-in-motion.pages.dev/)의 공개 ES 모듈을 `pages/clouds/gaussian/`에 가져와 원본의 가우시안 형태, 소광 적분, 그림자와 산란 계산을 사용한다. 출처와 원본 파일 해시는 해당 폴더의 `README.md`, `upstream.json`에 기록했다. 이전의 8bit 밀도 격자와 ray marching 구현은 제거했다.

## 입력

`script.ts`는 프리셋, seed, 태양 높이·방향, 밀도, 노출과 PNG 저장을 연결한다. `gaussian/camera-controls.js`는 회전, 이동, 휠·핀치 확대와 방향키를 처리한다. R은 시점 초기화, H는 설정 패널 전환이다. 새 요청이 들어오면 작업 중인 Worker를 종료하고 요청 번호로 오래된 결과를 거른다.

공간 좌표는 작품 내부의 world unit이다. 태양 각도는 UI에서 degree, 카메라 yaw와 pitch는 radian이다. 화면 크기는 CSS pixel, Canvas와 조명 버퍼는 device pixel이다.

## 중간 상태: 가우시안 원본과 캐시

`cloud-worker.ts`는 먼저 메모리가 아닌 디스크 캐시를 조회한다. 이미 준비한 seed가 있으면 가우시안과 LOD를 그대로 읽어 전달한다. 캐시가 없으면 다음 순서로 만든다.

1. `cloud.js`, `morphology.js`, `surface-detail.js`가 큰 덩어리와 작은 돌출부를 만들고 3D 가우시안으로 채운다. 기본 맑은 날 프리셋 seed 7351은 869,001개다. 각 항목은 위치 3개, 진폭, 축별 표준편차 3개와 seed를 Float32로 저장한다.
2. 작은 가우시안 미리보기를 먼저 보내 카메라를 조작할 수 있게 한다. 미리보기는 완료 상태나 저장 가능한 이미지로 취급하지 않는다.
3. 원본 밀도에서 여섯 방향의 국소 두께를 계산한다. WebGPU를 사용할 수 있으면 GPU에서 굽고, 사용할 수 없거나 실패하면 CPU로 같은 계산을 수행한다.
4. `spatial-lod.js`가 가우시안의 질량과 분포를 보존하는 병합 계층을 만든다. 가까운 영역은 작은 가우시안을 유지하고 멀리 있는 영역은 적은 수로 묶는다. 미세 계층 뒤의 큰 묶음은 전체 공분산을 저장한다.
5. 완성된 배열을 렌더러로 보내고, IndexedDB에도 저장한다. 화면 표시가 디스크 쓰기 완료를 기다리지 않는다.

`scene-cache.ts`는 원본과 LOD 배열에 중복 저장된 source 구간을 같은 backing buffer의 view로 바꾼다. 값을 양자화하거나 다시 샘플링하지 않는다. 기본 프리셋의 배열 메모리는 약 147 MB에서 105 MB로 줄어든다. 구조화 복제와 Worker 전달에서도 공유 관계를 보존한다.

메모리 LRU는 기본 240 MiB, coarse pointer 기기에서는 128 MiB이다. 디스크 캐시는 기본 320 MiB로 제한하고, 오래전에 저장한 항목부터 지운다. 버전이 바뀐 캐시도 삭제한다. Sunset과 Cumulus는 같은 geometry key를 사용한다. 저장 공간이 없거나 IndexedDB가 실패하면 원본 생성기로 돌아간다. 캐시는 이 브라우저와 origin에만 적용된다.

## 렌더 패스

| 순서 | 입력 → 출력 | 갱신 시점 |
| --- | --- | --- |
| 가시성·정렬 | 카메라와 LOD → 보이는 가우시안과 앞뒤 순서 | 시점·LOD 변경 |
| 태양 그림자 | 가우시안과 태양 → 512×384×65 광학 두께·밀도 | 태양·형태 변경 및 정지 샘플 진행 |
| 구름 | 카메라 광선, 가우시안, 그림자 → HDR 색과 투과율 | 새 샘플 |
| 누적 | 현재 HDR 샘플과 이전 평균 → 새 평균 | 최대 128샘플 |
| 후처리 | 평균, 하늘, 노출, 빛 번짐 → Canvas | 화면 갱신 |

가우시안은 중심에서 멀어질수록 밀도가 연속적으로 감소하는 3D 분포다. `shaders.js`는 광선이 가우시안을 통과한 양인 광학 두께를 해석적 적분으로 구한다. 두께가 커지면 투과율은 지수적으로 작아지고 뒤의 빛을 덜 통과시킨다. 따라서 화면을 작은 간격으로 걸어가며 밀도 격자를 조회하던 이전 방식의 해상도 제한이 없다.

가우시안은 앞에서 뒤 순서로 합성한다. 남은 투과율이 작아 이미 보이지 않는 픽셀은 opacity mask로 계산을 생략한다. 직접광은 태양 방향의 그림자 필드에서 얻으며, 국소 두께·미세 경계 방향·하늘 간접광과 다중 산란 근사를 합친다. 원본 shader와 상수는 수정하지 않았다.

`sampling.js`의 동일한 수열로 픽셀 위치, 빛, 흡수 지점을 조금씩 바꾼다. 샘플 번호로 수열을 정하므로 한 frame에 4개씩 제출해도 1개씩 128번 제출한 것과 같은 샘플들을 사용한다. 그림자 필드는 원본처럼 4회 재사용한다. 카메라가 움직일 때는 현재 필드를 재사용하며, 태양이나 형태가 바뀌면 새 필드를 만든다.

## 출력과 최적화

기본 출력은 CSS 크기 × DPR이며 DPR 상한은 원본과 같은 2다. 내부 cloud buffer도 출력 전체 크기다. 자동 성능 조절이 화면 해상도나 그림자 크기를 줄이지 않는다. UI의 원본 해상도 선택은 75%, 기본 레티나 선택은 100%다. 둘 다 최종 128샘플을 사용한다. 폭풍은 원본의 별도 번개·storm sample 정책을 따른다.

`refinement.ts`는 시점과 빛의 입력이 바뀌는 동안만 자동 LOD를 켠다. 마지막 변경 후 180 ms가 지나면 1x LOD로 바로 돌아가 최종 평균을 쌓는다. 원본의 여러 중간 LOD에서 128샘플씩 다시 수렴하던 작업을 생략한다. 정지 상태는 4샘플, 조작 중은 1샘플씩 제출한다. 노출과 빛 번짐은 기존 HDR 평균을 사용한다.

GPU fence로 한 제출의 완료를 확인한 뒤 다음 작업을 보낸다. 첫 완료 frame부터 로딩 덮개를 내리고, 최종 geometry·128샘플이 모두 준비된 뒤 저장 버튼을 활성화한다. PNG에는 작품 Canvas만 들어간다. context가 손실되거나 필요한 WebGL 기능이 없으면 오류와 재로드 안내를 표시한다.

## 검증

- `pnpm test pages/clouds scripts/public-routes.test.ts`: 원본 seed의 가우시안·조명 byte hash, LOD 공유 후 완전 일치, 캐시 메모리 제한, 원본 shader·상수 hash, 그림자 재사용, 샘플 순서, 조작 후 최종 화질 복원, 공개 경로.
- `pnpm typecheck`, `pnpm build`: TypeScript 연결부와 Web Worker 번들 확인.
- 기존 Chrome에서 원본과 같은 seed·카메라·태양·밀도·해상도를 맞춰 정지 이미지와 확대 화면을 비교한다. 프리셋, 새 seed, 연속 선택, 조명·밀도, 궤도, PNG 저장, 모바일 레이아웃과 콘솔도 확인한다.
- `window.clouds.diagnostics()`는 source 수, LOD, GPU 완료 기준의 상태, 해상도, 샘플, generation cache hit와 시간을 반환한다. Canvas dataset에도 주요 측정값을 노출한다. `?cache=off`는 디스크 캐시를 우회한다.

## 한계

새 seed는 원본 geometry와 LOD를 만들어야 하며, 처음 방문한 기기의 저장 캐시도 비어 있다. 첫 미리보기와 완성된 128샘플의 시간은 구분해야 한다. 조작은 즉시 반영하지만 최종 빛의 수렴에는 추가 시간이 필요하다. 기기·해상도별 60fps나 완전한 실시간 수렴을 보장하지 않는다. 원본의 조명과 다중 산란도 근사 모델이며 기상 시뮬레이션은 아니다.
