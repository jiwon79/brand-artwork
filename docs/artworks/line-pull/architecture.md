# Line Pull 아키텍처

Line Pull은 가로줄을 당겨 숨겨진 문구나 안쪽 선 표면을 여는 SVG 작품이다. 천이나 종이의 물리를 재현하는 대신, 선택한 선을 위아래 경계로 나누고 그 사이를 하나의 열린 영역으로 다룬다. 주변 선은 이 경계를 따라 휘고 문구와 안쪽 표면은 열린 영역 안에서만 보인다.

실행 흐름은 포인터 입력에서 시작한다. 입력이 어느 겹의 어느 선을 당기는지 정하면 당김 상태가 바뀌고 그 상태로 선과 열림 경계를 다시 계산한다. 경계 사이에 만든 다각형은 화면 표시, 다음 겹의 입력 범위, 문구 배치에 함께 쓰인다.

이 문서는 현재 코드의 입력 → 중간 상태 → 렌더 단계 → 출력 → 검증 순서를 설명한다. 세부 동작 기준은 [인터랙션 스펙](../../../pages/line-pull/spec.md), 정적 공유 카드 제작은 [공유 이미지 문서](./social-share-image.md)에 따로 정리되어 있다.

## 1. 입력

### 화면 좌표로 통일한다

포인터, 선, 열림 경계는 모두 stage 기준 CSS pixel 좌표를 쓴다. `localPoint()`가 브라우저의 포인터 좌표를 stage 안의 위치로 바꾸고 `resize()`가 SVG 좌표계와 stage 크기를 맞춘다. 기기 화면 밀도는 질감 파일을 고를 때만 쓰며 기하 계산에는 다시 곱하지 않는다.

선은 일정한 간격의 행으로 시작하지만 화면에는 완전한 직선으로 그리지 않는다. `restY()`가 각 행을 좌우 위치에 따라 조금 휘게 만든다. 이후 선택, 당김, 복원은 모두 이 정지 곡선을 기준으로 삼는다.

### 보이는 선만 선택한다

선 가까이에서 누르면 가장 가까운 선을 바로 선택한다. 줄 사이에서 누른 경우에는 아직 아무 선도 움직이지 않는다. 포인터가 이동한 경로와 정지 곡선이 처음 만나는 순간 해당 선을 활성화한다. 한 이벤트 사이에 포인터가 멀리 움직여도 경로 전체를 검사하므로 빠르게 선을 가로지를 때 입력을 놓치지 않는다.

안쪽 겹은 바깥쪽 틈으로 보이는 부분에서만 선택할 수 있다. 화면을 자르는 다각형을 입력 판정에도 사용하기 때문이다. 보이지 않는 선이 클릭되는 상태와 보이는 영역이 실제 입력 영역과 어긋나는 상태를 함께 막는다.

작품은 primary 포인터 하나만 소유한다. 정상적으로 놓은 입력과 브라우저가 취소한 입력을 구분해, 유지할 틈과 즉시 닫을 틈을 결정한다.

## 2. 중간 상태

### 겹과 당김을 분리한다

`Layer`는 화면에 남아 있는 선 표면이고 `pull`은 그 표면에서 진행 중인 당김이다. 바깥 겹은 항상 존재한다. 중첩 콘텐츠가 든 칸을 열 때만 안쪽 겹을 만들며 현재 구조는 바깥과 안쪽 두 겹까지만 허용한다.

| 상태 묶음 | 담고 있는 정보 |
| --- | --- |
| 입력 | 포인터를 소유한 겹, 선택한 선, 직전 포인터 위치 |
| 모양 | 정지선 위치, 당김 꼭짓점, 포인터가 요구하는 목표 위치 |
| 움직임 | 포인터 추종 여부, 복원 속도, 복원 중인지 여부 |
| 열림 | 경계로 만든 다각형과 포인터를 놓아도 틈을 유지할지 여부 |
| 표시 | 겹의 문구, 색, 글자 치수, SVG를 다시 계산해야 하는지 여부 |

포인터를 놓았다고 겹이 곧바로 사라지는 것은 아니다. 일반 문구가 든 틈은 정지선으로 돌아가고 안쪽 표면을 조작할 만큼 충분히 열린 틈은 그 모양을 유지한다. 이 상태에서 사용자는 바깥 틈 안의 선을 다시 당길 수 있다. 안쪽 당김을 정상적으로 놓으면 안쪽부터 부모까지 함께 복원을 시작한다.

취소, 포인터 소유권 상실, 창 이탈, 화면 크기 변경은 정상적인 놓기와 따로 처리한다. 복원 중에 다시 입력하면 잠금이 풀리기를 기다리지 않고 선택한 표면을 정리한 뒤 새 당김을 시작한다.

## 3. 렌더 단계

렌더 단계는 CPU에서 좌표를 계산하고 SVG DOM을 갱신하는 순서다. WebGL render target이나 후처리 shader는 사용하지 않는다.

### 필요한 동안만 프레임을 갱신한다

포인터 이벤트는 상태를 바꾸고 렌더를 요청한다. 같은 화면 주기에 요청이 여러 번 들어오면 `createFrameLoop()`가 하나로 합친다. 매 프레임 `advanceLayer()`가 포인터를 따라가는 위치나 복원 위치를 갱신하고 `renderFrame()`이 바뀐 겹의 SVG를 그린다.

당기는 동안 꼭짓점은 포인터의 목표 위치를 부드럽게 따라간다. 포인터를 놓으면 감쇠가 있는 스프링처럼 정지선으로 돌아온다. 화면 주기가 달라져도 움직임의 속도가 크게 바뀌지 않도록 지난 시간을 계산에 넣는다. 움직임이 끝나면 다음 프레임을 예약하지 않는다.

사용자가 reduced motion을 요청한 환경에서는 포인터 위치를 즉시 반영하고 복원 애니메이션을 생략한다. 겹을 열고 안쪽 표면을 조작하는 구조는 그대로 유지된다.

### 하나의 당김에서 두 경계를 만든다

![정지 상태의 선이 확대된 좌표를 거쳐 위아래 경계로 나뉘는 과정](../../assets/line-pull-opening.svg)

선택한 행의 정지 위치와 포인터가 만든 꼭짓점 사이의 거리가 기하 계산의 입력이다. `surfacePoint()`는 당김이 커질수록 현재 겹의 선 간격을 넓히고 꼭짓점 주변을 가로 방향으로도 벌린다. 확대의 기준은 열림 근처에 고정되어 포인터를 멀리 움직여도 변형의 중심이 함께 밀려나지 않는다.

선택한 선은 서로 다른 역할의 두 경계로 나뉜다. `boundaryPoint()`가 이웃 선의 가장자리를 따라가는 한쪽 경계를 만들고 `linePoint()`가 꼭짓점으로 끌려오는 다른 쪽 경계를 만든다. 주변 선은 꼭짓점에 한꺼번에 뭉치지 않고 각자의 간격을 조금 남긴 채 차례로 휘어진다. 위로 당길 때도 같은 계산에서 방향만 바뀐다.

이 변형은 빛이 굴절하는 렌즈 효과나 천의 물리 계산이 아니다. 모든 선의 화면 좌표를 당김 거리에 맞춰 다시 배치해 비슷한 인상을 만드는 기하 모델이다.

### 선과 마스크가 같은 경계를 공유한다

`sampleXs()`는 화면 너비를 따라 좌표를 뽑고 꼭짓점의 X 위치를 반드시 포함한다. 각 X에서 위쪽과 아래쪽 경계를 계산한 뒤, 두 경계를 반대 방향으로 이어 닫힌 다각형을 만든다.

이 다각형은 `clipPath`가 되어 배경과 문구를 드러낸다. 동시에 다음 겹의 입력 가능 영역과 글자를 놓을 수 있는 공간도 결정한다. 선의 겉모양과 콘텐츠 마스크를 별도 계산으로 맞추지 않으므로 둘 사이에 틈이 생기지 않는다.

### 안쪽 겹은 부모 안에 실제로 들어간다

![바깥 틈 안의 선 표면과 두 열림 영역을 모두 통과한 문구](../../assets/line-pull-nesting.svg)

안쪽 겹의 SVG 그룹은 부모의 `reveal` 그룹 안에 생성된다. 부모의 열림 마스크가 바깥을 자르고 자식의 열림 마스크가 그 안을 다시 자른다. 안쪽 콘텐츠는 화면과 두 틈에 모두 포함된 부분에서만 보인다. 별도 화면 위에 안쪽 그림을 올린 뒤 사각형으로 가리는 구조가 아니다.

부모의 모양이 그대로라면 안쪽 겹을 당길 때 부모 좌표를 다시 계산하지 않는다. 부모가 닫히면 그 안에 있던 자식 SVG와 clipPath도 함께 제거된다.

### 글자를 실제로 보이는 공간에 맞춘다

브라우저가 측정한 glyph bounds를 글자 배치의 기준으로 삼는다. 측정값은 저장해 두고 폰트가 늦게 로드된 경우에만 다시 읽는다. 포인터를 좌우로 움직여도 문구의 중심이 흔들리지 않도록 가로 중심은 stage 중앙에 둔다.

`fitCopyInOpenings()`는 글자 폭 전체에 걸쳐 위아래 경계를 검사한다. 글자가 잘리면 비율을 유지한 채 크기를 줄이고 가능한 세로 범위 안에서 원래 위치와 가까운 곳에 놓는다. 바깥 문구는 화면 너비에만 맞춰 틈이 열리면서 서서히 드러나게 한다. 안쪽 문구는 자기 틈과 모든 부모 틈 안에 들어가도록 더 엄격하게 맞춘다.

## 4. 출력

한 겹의 SVG는 열린 영역의 배경·문구·자식, 아래쪽 경계, 나머지 선의 순서로 쌓인다. 자식은 부모의 열린 영역 안에 있으므로 부모 선이 항상 그 위에 그려진다. 선의 확대는 SVG transform이 아니라 좌표 자체에 반영되며 stroke 두께는 별도로 유지한다.

표면의 미세한 입자는 SVG 필터로 매 프레임 만들지 않는다. `generate-line-pull-texture.mjs`가 화면 밀도별 WebP 타일을 미리 만들고 런타임은 알맞은 파일 하나를 전체 작품 위에 반복 합성한다. 당길 때는 바깥 겹의 확대 정도에 맞춰 이 질감 요소만 조금 확대한다.

최종 출력은 SVG 선, clipPath로 잘린 색면과 문구, 그 위의 질감으로 구성된다. 실시간 noise, 전체 화면 blur, 별도 WebGL pass는 없다.

## 5. 비용과 한계

움직이는 겹만 dirty 상태로 표시해 다시 그린다. 계산량은 화면에 있는 선의 수와 선마다 뽑는 가로 표본 수에 따라 늘어난다. 부모의 열림 다각형과 글자 치수는 가능한 한 재사용하고 아무것도 움직이지 않을 때는 프레임 루프를 멈춘다.

현재 기하 모델은 봉제, 접힘, 충돌, 굴절을 물리적으로 풀지 않는다. 선이 벌어지고 모이는 모양은 작품의 시각적 기준에 맞춘 경험적 계산이다. 글자 배치도 위쪽과 아래쪽 경계가 가로 방향으로 이어지는 현재 열림 모양을 전제로 하며 자기 교차나 여러 구멍이 있는 임의의 다각형에는 쓸 수 없다.

접근성 설정에 따라 움직임은 줄일 수 있지만 키보드만으로 선을 골라 여는 기능은 없다. Escape로 현재 조작이나 유지된 틈을 닫을 수는 있어도 포인터 조작 전체를 대신하지는 못한다.

순수 계산과 실제 브라우저 입력을 나눠 확인한다.

```sh
pnpm test pages/line-pull
pnpm typecheck
pnpm build
```

브라우저에서는 선 위와 줄 사이에서 시작하는 입력, 빠르게 선을 가로지르는 입력, 위아래 당김과 화면 가장자리, 복원 중 재입력을 확인한다. 이어서 바깥 틈을 유지하고 안쪽 선을 여는 흐름, 취소와 Escape, 화면 크기 변경, reduced motion, 폰트 지연 로딩을 점검한다. 움직임이 끝난 뒤 프레임 루프가 멈추고 닫힌 자식 그룹과 clipPath가 제거되는지도 확인해야 한다.
