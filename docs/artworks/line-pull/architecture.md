# Line Pull 아키텍처

Line Pull은 매 프레임 가로선의 좌표를 다시 계산해 포인터로 선을 당기고 틈을 여는 장면을 만든다. 천을 물리적으로 시뮬레이션하지는 않는다.

## 용어

| 용어 | 뜻 | 코드 |
| --- | --- | --- |
| 기준선 | 아무것도 당기지 않았을 때의 선 | `restingLineY()` |
| 선택선 | 포인터가 잡은 선 | `selectedLineIndex`, `selectedLineY` |
| 당김점 | 포인터를 따라 움직이며 선이 가장 많이 꺾이는 점 | `pullX`, `pullY` |
| 열린 틈 경계 | 선택선이 갈라져 생기는 두 가장자리 | `openingEdgePoint()`, `bentLinePoint()` |

## 장면이 만들어지는 순서

### 1. 선을 고른다

선 가까이에서 누르면 `lineAt()`이 포인터와 세로 거리가 가장 가까운 선을 선택한다. 줄 사이에서 누르면 `firstCrossing()`이 직전 포인터 위치부터 현재 위치까지의 경로를 확인해 처음 만난 선을 고른다. 포인터가 빠르게 움직여도 중간의 선을 놓치지 않는다.

### 2. 당김점을 움직인다

선을 고르면 선택선의 원래 위치와 당김점의 좌표를 저장한다. `pullX`는 포인터의 가로 위치를 바로 따라간다. `pullY`는 포인터의 세로 위치를 조금 늦게 따라가고, 포인터를 놓으면 선택선의 원래 위치로 돌아간다.

입력 이벤트는 목표 위치만 바꾼다. 실제 선 계산은 브라우저가 다음 화면을 그릴 때 한 번 실행한다. 움직임이 남아 있을 때만 다음 프레임을 요청한다.

### 3. 모든 선의 위치를 다시 구한다

![선택선을 당겼을 때 틈과 주변 선이 만들어지는 과정](../../assets/line-pull-opening.svg)

`sampleLineXs()`가 화면의 왼쪽부터 오른쪽까지 계산할 가로 위치를 고른다. 각 위치에서 다음 계산을 순서대로 적용한다.

1. `restingLineY()`로 기준선 위치를 구한다.
2. `spreadSurfacePoint()`로 당긴 거리만큼 전체 선의 간격을 벌린다.
3. `bentLinePoint()`로 선택선에 가까운 선일수록 당김점 쪽으로 더 크게 휘게 한다.

가로 방향으로는 당김점에서 가장 많이 휘고 화면 양쪽 끝으로 갈수록 덜 휜다. 세로 방향으로는 선택선과 가까운 선일수록 더 많이 끌려간다. 선 사이의 간격은 조금 남겨 여러 선이 한 점에 겹치지 않게 한다.

### 4. 틈을 만들고 SVG를 갱신한다

선택선은 두 경계로 나뉜다. `bentLinePoint()`가 포인터 쪽 경계를, `openingEdgePoint()`가 이웃선 쪽 경계를 만든다. 두 경계 사이가 열린 틈이다.

`pointsPath()`는 계산한 점들을 SVG 경로로 바꾼다. 일반 선은 새 경로 하나로 갱신하고, 선택선은 두 경계로 나누어 그린다. 두 경계를 이어 만든 도형 안에서만 숨겨진 내용이 보인다.

## 출력과 검증

한 프레임의 출력은 모든 선의 새 SVG 경로와 열린 틈의 경계다. 현재 방식은 물리 시뮬레이션이 아니라 작품의 모양에 맞춘 좌표 계산이다.

`geometry.test.ts`는 선과 틈의 좌표를, `frame-loop.test.ts`는 프레임 갱신과 정지를 검증한다. 전체 검증은 다음 명령으로 실행한다.

```sh
pnpm test pages/line-pull
pnpm typecheck
```

구체적인 동작값과 예외 처리는 [인터랙션 스펙](../../../pages/line-pull/spec.md)에 따로 둔다.
