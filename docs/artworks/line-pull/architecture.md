# Line Pull 아키텍처

Line Pull은 포인터로 가로줄 하나를 잡아당기면 주변 선까지 함께 휘어지며 틈이 열리는 SVG 작품이다. 천의 움직임을 물리적으로 계산하는 대신, 화면을 새로 그릴 때마다 각 선이 지나갈 위치를 다시 구한다.

전체 흐름은 다음과 같다.

> 포인터 입력 → 잡을 선 선택 → 당기는 점 갱신 → 모든 선의 위치 계산 → SVG 선과 열린 틈 갱신

세부 동작 기준은 [인터랙션 스펙](../../../pages/line-pull/spec.md)에 따로 정리되어 있다.

## 코드 지도

| 파일 | 역할 |
| --- | --- |
| [`script.ts`](../../../pages/line-pull/script.ts) | 포인터 입력을 받고 선을 선택한 뒤, 매 프레임 계산 결과를 SVG에 반영한다. |
| [`geometry.ts`](../../../pages/line-pull/geometry.ts) | 정지 상태의 선, 당겨진 선, 열린 틈의 위아래 경계 위치를 계산한다. |
| [`frame-loop.ts`](../../../pages/line-pull/frame-loop.ts) | 움직이는 동안만 브라우저의 다음 화면 갱신을 요청한다. |
| [`layers.ts`](../../../pages/line-pull/layers.ts) | 열린 틈 안에서 실제로 보이는 선만 선택할 수 있게 한다. |

## 1. 한 프레임을 만드는 순서

여기서 프레임은 브라우저가 화면을 한 번 새로 그리는 순간을 뜻한다. 포인터 이벤트가 들어오면 곧바로 모든 선을 그리지 않고, 먼저 목표 위치만 바꾼 뒤 `createFrameLoop()`에 화면 갱신을 요청한다. 같은 프레임 안에서 요청이 여러 번 들어와도 실제 계산은 한 번만 실행된다.

다음 프레임에서는 두 단계가 이어진다.

1. `advanceLayer()`가 선을 당기는 점을 포인터의 목표 위치 쪽으로 옮긴다.
2. `renderLayer()`가 그 점을 기준으로 모든 선의 새 위치를 구하고 SVG 경로를 바꾼다.

포인터를 놓으면 당기는 점은 원래 선으로 돌아간다. 아직 움직이고 있다면 다음 프레임을 요청하고, 제자리로 돌아오면 갱신을 멈춘다.

## 2. 어떤 선을 잡았는지 고르는 방법

선 바로 위에서 누르면 `lineAt()`이 포인터와 가장 가까운 선을 고른다. 각 선이 포인터와 같은 가로 위치에서 어디를 지나는지 구한 뒤, 세로 거리가 가장 가까운 선을 선택하는 방식이다. 안쪽 표면이 열린 상태라면 현재 틈을 통해 보이는 선만 후보가 된다.

줄과 줄 사이에서 누른 경우에는 아직 선을 고르지 않는다. 포인터가 움직이면 `firstCrossing()`이 직전 위치에서 현재 위치까지의 이동 경로를 검사한다. 그 경로와 가장 먼저 만난 선이 선택된다. 포인터 위치가 듬성듬성 들어와도 두 위치 사이의 경로 전체를 보기 때문에 선을 놓치지 않는다.

## 3. 포인터 위치를 당기는 점으로 바꾸는 방법

선을 고르면 다음 값을 저장한다.

| 값 | 뜻 |
| --- | --- |
| `originY` | 선택한 선이 원래 놓여 있던 세로 위치 |
| `apexX` | 현재 당기는 점의 가로 위치 |
| `apexY` | 화면에 그릴 당기는 점의 세로 위치 |
| `targetY` | 포인터가 요구하는 목표 세로 위치 |
| `grabOffsetY` | 선을 누른 위치와 선 중심의 차이 |

포인터가 움직이면 `apexX`는 포인터의 가로 위치를 바로 따라간다. `targetY`는 포인터의 세로 위치에서 `grabOffsetY`를 뺀 값이다. 처음 누른 간격을 그대로 유지하므로 선의 가장자리를 눌렀을 때도 선 중심이 갑자기 포인터 아래로 뛰지 않는다.

`apexY`는 `targetY`로 한 번에 이동하지 않고 프레임마다 조금씩 가까워진다. 그래서 포인터를 따라가는 움직임이 덜 딱딱하게 보인다. 포인터를 놓으면 같은 점이 감쇠 스프링처럼 `originY` 쪽으로 돌아간다.

## 4. 주변 선이 꺾이는 위치를 계산하는 방법

![선택한 선을 당겼을 때 틈과 주변 선이 만들어지는 과정](../../assets/line-pull-opening.svg)

먼저 `restY()`가 아무것도 당기지 않았을 때 각 선이 지나갈 위치를 만든다. 기본 선은 완전한 직선이 아니라 화면의 좌우 위치에 따라 조금 휘어 있다. 이후 계산은 모두 이 정지 상태를 기준으로 한다.

선을 당기면 `surfacePoint()`가 전체 선 간격을 조금 벌린다. 당기는 거리가 클수록 간격도 넓어진다. 선이 벌어지는 중심은 처음 틈이 열린 곳 근처에 고정된다. 포인터를 멀리 움직여도 화면 전체가 함께 밀려가지 않게 하기 위해서다.

그다음 `linePoint()`가 선마다 실제로 그릴 점을 구한다.

- 선택한 선에서 가까운 선일수록 더 많이 끌려간다.
- 가로 방향으로는 `apexX`에서 가장 많이 휘고, 화면 양쪽 끝으로 갈수록 휘는 정도가 줄어든다.
- 새로 영향을 받기 시작한 선은 갑자기 꺾이지 않고 조금씩 휘기 시작한다.
- 선들이 한 점에 완전히 겹치지 않도록 원래 간격의 일부를 남긴다.

선택한 선은 `linePoint()`와 `boundaryPoint()`로 두 번 계산한다. `linePoint()`가 포인터 쪽으로 끌려오는 경계를 만들고, `boundaryPoint()`가 이웃 선 쪽으로 이동하는 반대편 경계를 만든다. 두 경계 사이가 화면에서 보이는 틈이 된다. 위로 당길 때는 같은 계산의 방향만 반대로 바뀐다.

이 계산은 천의 접힘이나 충돌을 푸는 물리 시뮬레이션이 아니다. 당기는 점과 각 선 사이의 거리를 이용해 작품에 필요한 모양을 만드는 기하 계산이다.

## 5. 계산한 위치를 SVG 선으로 그리는 방법

`sampleXs()`는 화면 왼쪽부터 오른쪽까지 여러 가로 위치를 고르고, 포인터의 가로 위치인 `apexX`도 반드시 포함한다. 각 가로 위치에서 `linePoint()` 또는 `boundaryPoint()`를 실행하면 한 선을 이루는 점들이 나온다.

`pointsPath()`는 이 점들을 차례로 이어 SVG의 `M`과 `L` 명령으로 바꾼다. 일반 선은 `linePoint()`의 결과 하나로 그린다. 선택한 선은 두 계산 결과로 나누어 그려서 그 사이를 연다. 두 경계를 끝에서 이어 닫힌 도형을 만들고, 숨겨진 내용은 그 도형 안에서만 보이게 한다.

한 프레임을 계산하고 나면 모든 선의 새 SVG 경로와 열린 틈의 경계가 남는다. 포인터가 움직일 때마다 이 과정을 반복해 선이 이어서 휘는 장면을 만든다.
