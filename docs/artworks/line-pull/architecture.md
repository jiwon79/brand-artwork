# Line Pull 아키텍처

Line Pull은 가로줄을 당겨 숨겨진 문구나 안쪽 선 표면을 여는 SVG 작품이다. 실제 천이나 종이의 움직임을 계산하지는 않는다. 선택한 한 줄을 위아래 경계로 갈라 틈을 만든다. 주변 선은 그 틈에 맞춰 다시 배치한다. 문구와 안쪽 표면은 벌어진 틈을 통해서만 보인다.

포인터 입력이 들어오면 먼저 어느 표면의 어느 선을 잡았는지 찾는다. 그다음 포인터가 움직인 거리로 선과 틈의 모양을 다시 계산한다. 위아래 경계를 이어 만든 다각형은 세 곳에서 함께 쓴다. 콘텐츠가 보이는 범위, 안쪽 선을 누를 수 있는 범위, 문구가 들어갈 공간을 모두 이 다각형에서 구한다.

이 문서는 현재 코드의 입력 → 중간 상태 → 렌더 단계 → 출력 → 검증 순서를 설명한다. 세부 동작 기준은 [인터랙션 스펙](../../../pages/line-pull/spec.md), 정적 공유 카드 제작은 [공유 이미지 문서](./social-share-image.md)에 따로 정리되어 있다.

## 1. 입력

### 화면 좌표로 통일한다

여기서 `stage`는 작품이 차지하는 화면 영역이다. 포인터, 선, 열림 경계는 모두 이 영역을 기준으로 한 CSS 픽셀 좌표를 쓴다. `localPoint()`는 브라우저가 보낸 포인터 좌표를 `stage` 안의 위치로 바꾼다. `resize()`는 SVG 좌표계와 `stage` 크기를 맞춘다. 기기 화면 밀도는 질감 파일을 고를 때만 쓰며 선의 위치를 계산할 때는 사용하지 않는다.

선은 일정한 간격의 행으로 시작하지만 화면에는 완전한 직선으로 그리지 않는다. `restY()`가 각 행을 좌우 위치에 따라 조금 휘게 만든다. 이후 선택, 당김, 복원은 모두 이 정지 곡선을 기준으로 삼는다.

### 보이는 선만 선택한다

선 가까이에서 누르면 가장 가까운 선을 바로 선택한다. 줄 사이에서 누르면 아직 아무 선도 움직이지 않는다. 누른 채 움직이다가 포인터의 이동 경로가 선과 처음 만나는 순간 그 선이 당겨지기 시작한다. 브라우저가 이동 위치를 듬성듬성 전달하더라도 이전 위치와 현재 위치 사이의 경로 전체를 검사하므로 빠른 움직임도 놓치지 않는다.

안쪽 선은 바깥 틈으로 보이는 부분에서만 선택할 수 있다. 콘텐츠를 잘라내는 데 쓴 다각형을 입력 판정에도 그대로 쓰기 때문이다. 이 덕분에 화면에 가려진 선이 눌리거나, 보이는 영역과 실제 입력 영역이 어긋나는 일을 막을 수 있다.

작품은 `event.isPrimary`가 가리키는 기본 포인터 하나만 받는다. 사용자가 정상적으로 손을 뗐는지, 브라우저가 입력을 취소했는지도 구분한다. 이 결과에 따라 틈을 열린 채로 둘지 바로 닫을지 결정한다.

## 2. 중간 상태

### 겹과 당김을 분리한다

`Layer`는 한 장의 선 표면을 나타낸다. `pull`은 그 표면에서 현재 진행 중인 당김과 복원 상태다. 바깥 표면은 항상 존재하지만 안쪽 표면은 중첩 콘텐츠가 든 칸을 열었을 때만 만든다. 현재 작품은 바깥 표면과 안쪽 표면, 두 겹까지만 보여준다.

| 상태 묶음 | 담고 있는 정보 |
| --- | --- |
| 입력 | 현재 포인터 입력을 받는 겹, 선택한 선, 직전 포인터 위치 |
| 모양 | 정지선 위치, 당김 꼭짓점, 포인터가 요구하는 목표 위치 |
| 움직임 | 포인터 추종 여부, 복원 속도, 복원 중인지 여부 |
| 열림 | 경계로 만든 다각형과 포인터를 놓아도 틈을 유지할지 여부 |
| 표시 | 겹의 문구, 색, 글자 치수, SVG를 다시 계산해야 하는지 여부 |

포인터를 놓았다고 모든 틈이 곧바로 사라지는 것은 아니다. 일반 문구가 든 틈은 정지 상태로 돌아간다. 안쪽 표면을 조작할 만큼 크게 연 틈은 그대로 남는다. 사용자는 남은 틈 안의 선을 다시 당길 수 있다. 안쪽 선을 당겼다가 놓으면 안쪽과 바깥쪽이 함께 닫히기 시작한다.

취소, 포인터 소유권 상실, 창 이탈, 화면 크기 변경은 정상적인 놓기와 따로 처리한다. 복원 중에 다시 입력하면 잠금이 풀리기를 기다리지 않고 선택한 표면을 정리한 뒤 새 당김을 시작한다.

## 3. 렌더 단계

여기서 렌더 단계란 CPU에서 좌표를 계산하고 SVG 요소에 반영하는 순서를 말한다. WebGL의 별도 렌더 타깃이나 후처리 셰이더는 사용하지 않는다.

### 필요한 동안만 프레임을 갱신한다

포인터 이벤트는 상태를 바꾼 뒤 화면 갱신을 요청한다. 브라우저가 화면을 한 번 그리는 동안 요청이 여러 번 들어오면 `createFrameLoop()`가 하나로 합친다. 다음 프레임에서 `advanceLayer()`가 당겨진 위치나 복원 중인 위치를 계산한다. 이어서 `renderFrame()`이 바뀐 겹의 SVG를 갱신한다.

당기는 동안 꼭짓점은 포인터의 목표 위치를 부드럽게 따라간다. 포인터를 놓으면 감쇠가 있는 스프링처럼 정지선으로 돌아온다. 화면 주기가 달라져도 움직임의 속도가 크게 바뀌지 않도록 지난 시간을 계산에 넣는다. 움직임이 끝나면 다음 프레임을 예약하지 않는다.

사용자가 `prefers-reduced-motion`을 설정한 환경에서는 포인터 위치를 즉시 반영하고 복원 애니메이션을 생략한다. 겹을 열고 안쪽 표면을 조작하는 구조는 그대로 유지된다.

### 하나의 당김에서 두 경계를 만든다

![정지 상태의 선이 확대된 좌표를 거쳐 위아래 경계로 나뉘는 과정](../../assets/line-pull-opening.svg)

선 위에서 포인터가 붙잡아 움직이는 점을 당김 꼭짓점이라고 부른다. 선택한 선의 원래 위치와 이 꼭짓점 사이의 거리가 기하 계산의 입력이다. `surfacePoint()`는 많이 당길수록 현재 표면의 선 간격을 넓히고 꼭짓점 주변을 가로 방향으로도 벌린다. 변형의 기준점은 처음 열린 곳 근처에 고정된다. 포인터를 멀리 움직여도 선이 벌어지는 중심까지 따라 밀려나지 않게 하기 위해서다.

선택한 선은 서로 다른 역할의 두 경계로 나뉜다. `boundaryPoint()`가 이웃 선의 가장자리를 따라가는 한쪽 경계를 만들고 `linePoint()`가 꼭짓점으로 끌려오는 다른 쪽 경계를 만든다. 주변 선은 꼭짓점에 한꺼번에 뭉치지 않고 각자의 간격을 조금 남긴 채 차례로 휘어진다. 위로 당길 때도 같은 계산에서 방향만 바뀐다.

이 변형은 빛이 굴절하는 렌즈 효과나 천의 물리 계산이 아니다. 모든 선의 화면 좌표를 당김 거리에 맞춰 다시 배치해 비슷한 인상을 만드는 기하 모델이다.

### 선으로 그린 틈과 콘텐츠가 보이는 범위를 맞춘다

화면에서는 두 경계선 사이가 벌어진 틈처럼 보인다. 이 틈과 실제로 콘텐츠가 나타나는 범위가 조금이라도 어긋나면, 선 밖으로 배경이 새거나 선 안쪽에 가느다란 빈 공간이 생긴다.

이를 막기 위해 `sampleXs()`가 화면 너비를 따라 여러 X 위치를 고른다. 각 X에서 위쪽 경계점과 아래쪽 경계점을 한 번씩 계산한다. 화면의 두 경계선은 이 점들로 그린다. 콘텐츠를 잘라낼 닫힌 다각형도 같은 점들을 이어서 만든다.

SVG의 `clipPath`는 지정한 도형 안쪽만 보이게 하는 잘라내기 영역이다. 배경과 문구에 이 다각형을 `clipPath`로 적용하면 두 경계선 사이에서만 콘텐츠가 보인다. 경계선과 잘라내기 영역이 같은 점들을 사용하므로 화면에 그린 틈과 콘텐츠가 드러나는 범위가 정확히 맞는다. 이 다각형은 안쪽 선의 입력 범위와 문구가 들어갈 공간을 계산할 때도 다시 쓴다.

### 안쪽 표면은 바깥 틈 안에 넣는다

![바깥 틈 안의 선 표면과 두 열림 영역을 모두 통과한 문구](../../assets/line-pull-nesting.svg)

중첩 칸을 열면 바깥 틈 안에 새로운 선 표면이 나타난다. 문서와 코드에서는 먼저 연 바깥 표면을 부모 겹, 그 안에서 새로 만든 표면을 자식 겹이라고 부른다.

`reveal`은 SVG의 특별한 기능이 아니다. 이 프로젝트가 일반 SVG 그룹인 `<g>`에 붙인 이름이다. 한 겹의 틈을 통해 보여줄 배경, 문구, 자식 겹을 이 그룹 안에 모아 둔다. `reveal` 그룹에는 앞 절에서 만든 `clipPath`가 걸려 있다. 그래서 그룹 안의 요소는 벌어진 틈 안에서만 보인다.

`createView()`는 자식 겹의 SVG 그룹을 부모 겹의 `reveal` 안에 넣는다. 브라우저는 먼저 부모의 틈 바깥을 잘라낸다. 자식 겹이 열리면 자식의 틈 바깥도 한 번 더 잘라낸다. 따라서 안쪽 문구는 바깥 틈과 안쪽 틈에 모두 포함된 부분에서만 보인다.

부모 겹의 모양이 바뀌지 않았다면 안쪽 선을 당기는 동안 바깥 선의 좌표를 다시 계산할 필요가 없다. 부모 겹이 닫히면 그 안에 들어 있던 자식 SVG와 `clipPath`도 함께 제거된다.

### 글자를 실제로 보이는 공간에 맞춘다

브라우저가 측정한 글자의 실제 경계 상자(`glyph bounds`)를 배치 기준으로 삼는다. 측정값은 저장해 두고 폰트가 늦게 로드된 경우에만 다시 읽는다. 포인터를 좌우로 움직여도 문구가 따라 흔들리지 않도록 가로 중심은 `stage` 중앙에 고정한다.

`fitCopyInOpenings()`는 글자 폭 전체에 걸쳐 위아래 경계를 검사한다. 글자가 잘리면 비율을 유지한 채 크기를 줄이고 가능한 세로 범위 안에서 원래 위치와 가까운 곳에 놓는다. 바깥 문구는 화면 너비에만 맞춰 틈이 열리면서 서서히 드러나게 한다. 안쪽 문구는 자기 틈과 모든 부모 틈 안에 들어가도록 더 엄격하게 맞춘다.

## 4. 출력

한 겹의 SVG는 틈 안에 보일 배경·문구·자식 겹을 먼저 그린다. 그 위에 아래쪽 경계와 나머지 선을 그린다. 자식 겹은 부모의 틈 안에 들어 있으므로 부모 선이 항상 자식보다 앞에 보인다. 선의 확대는 SVG `transform`이 아니라 각 점의 좌표에 직접 반영한다. `stroke` 두께는 따로 유지한다.

표면의 미세한 입자는 SVG 필터로 매 프레임 만들지 않는다. `generate-line-pull-texture.mjs`가 화면 밀도별 WebP 타일을 미리 만들고 런타임은 알맞은 파일 하나를 전체 작품 위에 반복 합성한다. 당길 때는 바깥 겹의 확대 정도에 맞춰 이 질감 요소만 조금 확대한다.

최종 화면은 SVG 선, `clipPath`로 잘린 색면과 문구, 그 위에 덧씌운 질감으로 이루어진다. 실시간 노이즈, 전체 화면 블러, 별도 WebGL 패스는 사용하지 않는다.

## 5. 비용과 한계

내용이 바뀐 겹만 `dirty`로 표시해 다시 그린다. 계산량은 화면에 있는 선의 수와 선마다 뽑는 가로 표본 수에 따라 늘어난다. 부모의 열림 다각형과 글자 치수는 가능한 한 재사용한다. 아무것도 움직이지 않을 때는 프레임 루프를 멈춘다.

현재 기하 모델은 봉제, 접힘, 충돌, 굴절을 물리적으로 풀지 않는다. 선이 벌어지고 모이는 모양은 작품의 시각적 기준에 맞춘 경험적 계산이다. 글자 배치도 위쪽과 아래쪽 경계가 가로 방향으로 이어지는 현재 열림 모양을 전제로 하며 자기 교차나 여러 구멍이 있는 임의의 다각형에는 쓸 수 없다.

접근성 설정에 따라 움직임은 줄일 수 있지만 키보드만으로 선을 골라 여는 기능은 없다. Escape로 현재 조작이나 유지된 틈을 닫을 수는 있어도 포인터 조작 전체를 대신하지는 못한다.

브라우저에서는 선 위와 줄 사이에서 시작하는 입력, 빠르게 선을 가로지르는 입력, 위아래 당김과 화면 가장자리, 복원 중 재입력을 확인한다. 이어서 바깥 틈을 유지하고 안쪽 선을 여는 흐름, 취소와 Escape, 화면 크기 변경, `prefers-reduced-motion`, 폰트 지연 로딩을 점검한다. 움직임이 끝난 뒤 프레임 루프가 멈추고 닫힌 자식 그룹과 `clipPath`가 제거되는지도 확인해야 한다.
