# 반려동물 Cursor Artwork 만들기

이 문서는 반려동물 사진으로, 커서나 터치 위치를 따라 시선을 돌리는 웹 작품을 직접 만드는 방법을 설명한다. 화면에는 영상이 아니라 미리 만든 여러 장의 사진 중 한 장이 표시된다.

방법 자체는 무료로 따라 할 수 있지만 이미지·영상 생성 서비스의 크레딧, 저장 공간과 호스팅 비용은 별도로 들 수 있다.

## 전체 흐름

1. 반려동물 원본 사진을 준비한다.
2. 오른쪽·위·왼쪽을 보는 기준 이미지를 만든다.
3. 기준 이미지 사이를 연결하는 짧은 영상을 만든다.
4. 영상을 실제 시선 방향 순서로 골라 약 120장의 프레임으로 정리한다.
5. 모든 프레임의 색, 배경과 동물 크기를 맞춘다.
6. 눈 위치에서 커서까지의 각도를 계산해 가장 가까운 프레임을 보여준다.
7. 최종 프레임만 외부 저장소에 올리고 웹 페이지에서 불러온다.

## 1. 필요한 도구

정확히 같은 제품을 사용할 필요는 없다. 다음 두 종류의 도구가 있으면 된다.

### AI 코딩 도구

로컬 파일을 읽고 수정하며 터미널 명령을 실행할 수 있어야 한다.

- Codex
- Claude Code
- Cursor
- 그 밖의 agent형 코딩 도구

### 이미지·영상 생성 도구

같은 동물의 정체성을 유지하면서 기준 이미지와 시작·끝 프레임 영상을 만들 수 있어야 한다.

- ComfyUI 또는 ComfyUI Cloud
- Higgsfield
- Runway
- 시작 이미지와 끝 이미지를 지정할 수 있는 다른 이미지·영상 생성 서비스

두 도구가 API, MCP, plugin 등으로 직접 연결되어 있으면 편하지만 필수는 아니다. 생성 결과를 내려받아 코딩 도구가 접근할 수 있는 작업 폴더에 넣는 방식으로도 만들 수 있다.

### 있으면 좋은 환경

- Node.js와 TypeScript 웹 프로젝트
- FFmpeg: 영상의 프레임 확인과 추출
- 이미지 처리 라이브러리: 크기·색·alpha 보정
- Cloudflare R2, S3 같은 object storage와 정적 웹 호스팅

## 2. 시작 전에 준비할 사진

반려동물의 얼굴과 무늬가 선명한 원본 사진 3~5장을 준비한다.

- 정면 또는 살짝 옆을 보는 사진
- 왼쪽과 오른쪽 얼굴 무늬를 확인할 수 있는 사진
- 귀, 눈, 코, 턱이 잘리지 않은 사진
- 강한 필터, 모션 블러와 복잡한 그림자가 없는 사진
- 가능하면 원본 해상도 사진

한 장만으로도 생성할 수 있지만 비대칭 무늬나 귀 모양이 중간에 바뀔 가능성이 커진다. 다른 사람의 동물 사진을 사용할 때는 반드시 허락을 받는다.

## 3. 최종 규격을 먼저 정한다

생성을 시작하기 전에 모든 결과의 공통 규격을 고정한다.

| 항목 | 권장값 | 이유 |
| --- | --- | --- |
| 화면 비율 | 9:16 | 데스크톱과 모바일 세로 화면에 함께 사용하기 쉽다. |
| 작업 크기 | 576 × 1024 이상 | 얼굴과 수염을 유지하면서 웹 용량을 조절하기 좋다. |
| 방향 순서 | 오른쪽 → 위 → 왼쪽 → 아래 → 오른쪽 | 한 바퀴가 끊기지 않는 원형 순서가 된다. |
| 최종 프레임 | 약 120장 | 3° 간격에 가까워 움직임과 용량의 균형이 좋다. |
| 배경 | 평평한 순백 또는 투명 | 프레임 사이 배경 깜빡임을 피할 수 있다. |
| 고정점 | 몸통 아래 중앙 | 모바일 높이가 변해도 동물이 화면 아래에 붙어 있다. |

프레임 수는 줄일 수 있다. 다만 눈과 머리가 빠르게 움직이는 구간과 네 기준 방향 주변을 먼저 보존한다.

## 4. 기준 이미지를 만든다

먼저 오른쪽, 위, 왼쪽을 보는 기준 이미지를 만든다. 아래 포즈까지 별도로 만들면 더 안정적이지만, 비용을 줄이려면 아래 포즈는 영상 안에서 찾을 수 있다.

모든 기준 이미지에서 다음 항목이 같아야 한다.

- 얼굴과 몸통의 크기
- 카메라 위치와 crop
- 털 색, 화이트밸런스, 대비와 채도
- 귀와 수염의 모양
- 비대칭 얼굴 무늬
- 몸통 아래 위치
- 순백 배경

왼쪽 포즈를 오른쪽 이미지의 단순 좌우 반전으로 만들지 않는다. 얼굴의 비대칭 무늬도 함께 뒤집히기 때문이다.

### 기준 이미지 요청 예시

```text
Use the attached pet photos as identity references.
Create a photorealistic 9:16 portrait of the exact same animal looking toward the TOP EDGE of the screen.
Keep the asymmetric facial markings, fur boundaries, ears, body, camera, crop, face scale, exposure, white balance, contrast, and saturation unchanged.
Keep both eyes naturally visible.
Use a flat pure white background with no floor, shadow, gradient, props, text, or watermark.
Leave comfortable white margin around both ears and the face.
```

`TOP EDGE`를 `LEFT EDGE`, `RIGHT EDGE` 또는 `BOTTOM EDGE`로 바꿔 각 방향을 만든다. 모델 기준의 왼쪽·오른쪽이 아니라 화면의 가장자리 방향이라고 명시하는 것이 중요하다.

## 5. 방향 사이의 영상을 만든다

기준 이미지를 first frame과 last frame으로 사용해 다음 세 구간을 만든다.

1. 오른쪽 → 위
2. 위 → 왼쪽
3. 왼쪽 → 아래 → 오른쪽

상단 두 구간은 각각 1/4원이고, 마지막 구간은 아래쪽 1/2원이다. 모델이 긴 동작을 잘 유지하지 못하면 아래 구간도 `왼쪽 → 아래`, `아래 → 오른쪽`으로 나눈다.

### 위쪽 구간 요청 예시

```text
Create one smooth continuous UPPER circular head-and-eye tracking motion in SCREEN coordinates: RIGHT → TOP → LEFT.
Keep the exact animal identity, asymmetric markings, body, camera, crop, face scale, exposure, and flat pure white background fixed.
Move only the head, eyes, and ears as naturally required.
Never look downward, blink intentionally, zoom, reframe, mirror, sway the torso, add shadows, or change the background.
```

### 아래쪽 구간 요청 예시

```text
Create one smooth continuous LOWER circular head-and-eye tracking motion in SCREEN coordinates: LEFT → BOTTOM → RIGHT.
At the middle of the motion, look clearly toward the BOTTOM EDGE while keeping both eyes naturally visible.
Keep the exact animal identity, asymmetric markings, body, camera, crop, face scale, exposure, white balance, contrast, saturation, and flat pure white background fixed.
Never look upward, blink intentionally, zoom, reframe, mirror, sway the torso, add shadows, or change the background.
```

영상 모델이 “중간에 아래를 본다”는 지시를 정확한 시간 50%에 지킨다고 가정하지 않는다. 실제 결과를 보고 아래 포즈가 나온 프레임을 찾는다.

## 6. 시간 대신 실제 시선 방향으로 프레임을 고른다

영상에서 일정한 시간 간격으로 프레임을 뽑으면 움직임이 고르지 않을 수 있다. 영상 모델은 시작과 끝에서 멈추거나 구간마다 머리 회전 속도를 바꾸기 때문이다.

다음 순서로 선택한다.

1. 오른쪽, 위, 왼쪽, 아래 기준 프레임을 먼저 찾는다.
2. 각 기준 방향 사이에서 실제 시선이 조금씩 변하는 프레임을 고른다.
3. 같은 자세가 이어지는 정지 구간은 건너뛴다.
4. 눈 깜빡임, 몸통 흔들림, zoom과 무늬가 변한 프레임은 제외한다.
5. 마지막 오른쪽과 첫 오른쪽이 자연스럽게 이어지는지 확인한다.

120장을 사용할 경우 기준 index는 다음처럼 배치할 수 있다.

| 프레임 | 방향 |
| --- | --- |
| 001 | 오른쪽 |
| 031 | 위 |
| 061 | 왼쪽 |
| 091 | 아래 |
| 120 다음 | 다시 001 오른쪽 |

optical flow나 두 장의 crossfade로 없는 자세를 억지로 만들기보다, 실제 생성 영상에 존재하는 단일 프레임을 선택하는 편이 얼굴과 수염을 안정적으로 유지한다.

## 7. 120장의 색과 크기를 맞춘다

이미지 모델로 만든 기준 이미지와 영상 모델의 중간 프레임은 밝기와 색감이 다를 수 있다. 최종 변환 전에 모든 프레임을 같은 canvas에 맞춘다.

### 색

- 주황색, 검은색, 흰색 등 주요 털 영역을 나눠 비교한다.
- 양 끝 기준 이미지 사이의 밝기, 채도와 RGB balance를 중간 프레임에 보간한다.
- 배경 순백을 털 색 측정에 섞지 않는다.

### 배경

- 캔버스 가장자리와 연결된 밝고 저채도인 배경만 투명하게 만든다.
- 흰 털, 눈 하이라이트와 수염은 불투명하게 남겨야 한다.
- 배경 전체를 단순 색상 threshold로 지우면 흰 털까지 사라질 수 있다.

### 크기

- 각 프레임의 동물 alpha 면적과 얼굴 bounding box를 비교한다.
- 기준 이미지와 영상이 만나는 지점에서 갑자기 확대되거나 축소되는지 확인한다.
- 작은 차이는 웹에서 frame별 scale anchor를 보간해 보정할 수 있다.
- scale의 기준점은 아래 중앙으로 두어 몸통 아래가 움직이지 않게 한다.

최종 파일은 `frame-001.webp`부터 `frame-120.webp`까지 연속 번호로 저장한다.

## 8. 눈 기준점을 기록한다

커서 방향을 화면 중앙에서 계산하면 머리가 움직일 때 시선이 어긋난다. 오른쪽, 위, 왼쪽, 아래 포즈마다 두 눈 사이의 기준점을 기록한다.

원본의 폭을 `W`, 높이를 `H`, 측정한 눈 위치를 `(x, y)`라고 하면 저장값은 다음과 같다.

```text
normalizedX = x / W
normalizedY = y / H
```

중간 프레임의 기준점은 인접 방향의 값을 선형 보간한다. 아래 포즈에서 머리가 좌우로 이동했다면 `x = 0.5`로 강제하지 말고 실제 위치를 사용한다.

## 9. 커서 각도를 프레임으로 바꾼다

프레임 `i`의 기대 시선 각도를 원 한 바퀴에 배치한다.

```text
gazeAngle(i) = -(i / frameCount) × 2π
```

커서가 움직일 때 모든 프레임 후보에 대해 다음 값을 비교한다.

1. 그 프레임의 눈 기준점을 화면 좌표로 바꾼다.
2. 눈 기준점에서 커서까지 `atan2` 각도를 구한다.
3. 프레임의 기대 시선 각도와의 원형 각도 차이를 구한다.
4. 차이가 가장 작은 프레임을 선택한다.

현재 프레임을 목표 프레임으로 즉시 바꾸면 딱딱하게 보일 수 있다. 원 위의 최단 방향으로 진행률을 보간하고 가장 가까운 정수 프레임을 표시하면 자연스럽다. `120 → 001` 경계에서는 단순 뺄셈 대신 원형 wrap을 사용한다.

## 10. 웹 페이지를 구성한다

최소 구성은 다음과 같다.

- 프레임을 보여주는 `<img>` 하나
- 커서·터치 입력을 받는 전체 화면 stage
- 모든 프레임을 미리 불러오는 loader
- 눈 위치와 scale anchor가 들어 있는 manifest
- 각도 계산과 프레임 교체 코드

처음부터 첫 이미지를 보여주면 나머지 프레임이 준비되기 전에 상호작용이 시작될 수 있다. 로딩 중에는 동물을 숨기고 `Loading 0%`처럼 실제 decode 진행률만 표시한다. 모든 프레임이 준비된 뒤 이미지와 상호작용을 함께 켠다.

모바일에서는 `100vh` 대신 `100dvh`를 사용하고 이미지의 아래 중앙을 viewport 아래에 고정한다. 그래야 주소창 높이가 변해도 몸통 아래가 뜨지 않는다.

## 11. 파일을 저장하고 공유한다

120장을 앱 저장소에 직접 넣으면 Git과 배포 용량이 커진다. 최종 WebP만 object storage에 평평하게 저장하고 웹 페이지는 manifest를 통해 URL을 만든다.

```text
cursor-animal/<random-id>/manifest.json
cursor-animal/<random-id>/frame-001.webp
...
cursor-animal/<random-id>/frame-120.webp
```

공유용 경로에는 동물 이름이나 사용자 정보를 넣지 않고 랜덤 ID를 사용한다. 랜덤 URL은 인증이 아니므로 민감한 사진이나 생성 원본은 공개 storage에 올리지 않는다.

manifest를 갱신할 때는 version 값을 프레임 URL에 붙여 이전 브라우저 cache와 구분한다. 프레임을 먼저 올리고 manifest를 마지막에 올리면 불완전한 세트가 공개되는 시간을 줄일 수 있다.

## 12. 최종 검수표

### 정체성

- [ ] 얼굴의 비대칭 무늬가 모든 방향에서 유지된다.
- [ ] 귀, 눈, 코, 턱과 수염이 프레임 밖으로 잘리지 않는다.
- [ ] 눈 깜빡임이나 다른 동물처럼 변하는 프레임이 없다.

### 움직임

- [ ] 오른쪽 → 위 → 왼쪽 → 아래 → 오른쪽 순서다.
- [ ] 기준 방향이 실제 화면 가장자리를 향한다.
- [ ] 첫 프레임과 마지막 프레임 연결이 자연스럽다.
- [ ] 커서와 눈의 시선이 대각선에서도 맞는다.

### 화면

- [ ] 배경이 완전히 흰색이고 회색 얼룩이 없다.
- [ ] 구간 접점에서 밝기, 채도와 크기가 갑자기 변하지 않는다.
- [ ] 로딩 중에는 동물이 보이지 않고 진행률만 표시된다.
- [ ] 모바일에서 몸통 아래와 viewport 아래가 맞는다.

### 배포

- [ ] 프레임 번호가 연속이며 중복과 누락이 없다.
- [ ] 생성 원본과 사용자 원본 사진은 공개 storage에 없다.
- [ ] 공유 URL에서 모든 프레임이 준비된 뒤 상호작용이 시작된다.

## 13. 자주 생기는 문제

| 문제 | 주된 원인 | 해결 방향 |
| --- | --- | --- |
| 얼굴 무늬가 좌우로 바뀐다 | 수평 반전 또는 정체성 drift | 여러 원본 사진을 제공하고 mirror 금지를 명시한다. |
| 위나 아래에서 크기가 튄다 | 서로 다른 생성 구간의 framing 차이 | alpha 면적을 측정하고 접점 scale을 보정한다. |
| 중간 프레임만 회색 배경이다 | 영상 압축과 조명 변화 | 연결된 배경을 투명화하고 CSS 흰색 위에 합성한다. |
| 아래 커서와 시선이 맞지 않는다 | 시간 중간 프레임을 아래로 가정했다 | 실제 아래 포즈를 찾고 양쪽 구간을 따로 샘플링한다. |
| 대각선에서 시선이 어긋난다 | 모든 프레임에 화면 중앙을 사용했다 | 방향별 눈 기준점을 기록하고 중간값을 보간한다. |
| 첫 방문에 고양이가 깜빡인다 | 일부 프레임만 준비된 상태로 표시했다 | 전체 preload와 decode가 끝날 때까지 숨긴다. |

## 14. AI 코딩 도구에 전달할 시작 요청

아래 요청을 현재 사용하는 AI 코딩 도구에 붙여 넣고, 프로젝트 구조와 생성 도구에 맞게 경로만 조정한다.

```text
반려동물 사진으로 커서와 터치 방향을 따라 시선을 돌리는 9:16 웹 작품을 만들어줘.

최종 출력은 오른쪽 → 위 → 왼쪽 → 아래 → 오른쪽 순서의 WebP 프레임 약 120장으로 구성해. 화면에는 매 순간 이미지 한 장만 표시하고, 모든 프레임이 preload·decode되기 전에는 동물을 숨긴 채 중앙에 실제 로딩 진행률을 보여줘.

각 기준 방향마다 두 눈 사이의 정규화 좌표를 calibration으로 저장해. 커서가 움직이면 각 후보 프레임의 눈 기준점에서 커서까지의 atan2 각도와 그 프레임의 기대 시선 각도를 비교해서 가장 가까운 프레임을 선택해. 원형 경계에서는 최단 방향으로 부드럽게 보간해.

모바일에서는 100dvh를 사용하고 동물 이미지의 transform origin과 아래쪽을 화면 아래 중앙에 고정해. 생성 원본은 웹 저장소에 넣지 말고, 최종 프레임과 manifest만 object storage에서 불러오게 해.

먼저 내가 가진 원본 사진과 생성된 기준 이미지·영상의 경로를 확인하고, 필요한 파일이 없으면 어떤 방향 이미지와 영상이 필요한지 목록부터 알려줘.
```
