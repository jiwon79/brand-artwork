# Line Pull — 인터랙티브 라인 리빌 스펙

## 기준과 범위

제공 영상 **초반의 완성된 모션**을 기준으로 한다. 뒤쪽 제작 과정의 선택 핸들이나 고정된 네 줄 묶음은 인터랙션 규칙으로 사용하지 않는다. 화면 어디에서든 시작해 원하는 높이까지 당길 수 있으며, 아래로 당기는 경우를 설명의 기준으로 삼는다. 위로 당길 때는 같은 규칙을 반전한다.

## 입력과 활성화

- 마우스·펜·터치의 첫 번째 포인터만 받는다.
- 선 위를 누르면 해당 선을 활성화한다. 선 근처의 허용 오차 안에서 잡았을 때는 클릭 순간 선이 튀지 않도록 잡은 위치와 선 사이의 간격을 유지한다.
- 줄 사이에서 시작하면 교차 전에는 화면을 변형하지 않는다. 포인터의 이전 위치부터 현재 위치까지의 구간과 실제 곡선의 교점을 구해, 가장 먼저 만난 선을 활성화한다. 빠른 대각선 이동과 곡률 때문에 생기는 수평 교차도 처리한다.
- 가로 위치는 연속값이며 세로 당김에는 고정 높이·줄 개수 제한이 없다. 포인터 캡처로 화면 밖 이동도 받는다.
- 기본 줄 간격은 56 CSS px로, 이전 70px의 80%다.
- 놓은 뒤 복원 중이어도 새 입력은 즉시 시작한다. 별도 대기 시간이나 입력 잠금은 없다.

## 위쪽 경계

활성선은 위쪽 경계와 아래쪽 당김 경계로 나뉜다. 위쪽 경계는 당김 거리에 비례해 계속 올라가지 않는다.

1. 당김 초기에 **확대된 표면의 바로 위 선**으로 빠르게 접근한다.
2. 두 선의 가장자리가 맞닿을 때까지 접근한다. 중심선은 한 줄 두께만큼 떨어져 남으므로, 붙은 부분은 한 줄이 아니라 **두 줄을 합한 두께**가 된다. 기본 선 두께 3 CSS px에서는 약 6 CSS px이며, 곡률이 있는 곳은 기울기를 고려해 간격을 계산한다. 위로 당길 때도 방향을 반전해 같은 규칙을 쓴다.
3. 이후에는 바로 위 선을 포함한 위쪽 격자와 함께 아주 조금씩 이동한다. 이 추가 이동량은 당김이 길어질수록 증가 속도가 작아진다.

`boundaryEase`는 바로 위 선에 접근하는 거리, `boundaryCreep`은 붙은 뒤 추가 이동을 조절한다. `geometry.ts`의 `boundaryPoint`와 위쪽 `linePoint`가 동일한 추가 이동량을 사용한다. 맞닿음 계산의 기울기는 렌즈의 확대율뿐 아니라 확대 기준이 되는 곡선의 기울기도 포함한다.

## 아래쪽 꺾임

주 당김 경계의 꼭짓점은 포인터를 짧게 지연 추종한다. 주변 선들의 꼭짓점은 같은 X에 정렬되지만 **서로 다른 Y**를 가진다. 아래 선일수록 조금 더 아래에 남아, 모든 선이 한 점으로 겹치지 않는다.

`apexSpacing`은 확대된 선 간격 중 꼭짓점 사이에 남길 비율이다. 기본값 `0.16`에서는 충분히 당겨진 인접 선끼리 약 11px의 간격이 남는다. 아직 완전히 끌려오지 않은 선은 더 넓은 간격을 유지한다.

새 선이 영향 범위에 들어올 때 path를 갑자기 교체하지 않는다. 평평한 상태부터 꺾임이 연속적으로 커지므로 당김·되돌림 양쪽에서 합류 순간의 점프가 없다. 포인터 아래쪽의 나머지 격자도 확대된 표면의 일부로 조금 이동한다.

## 확대와 콘텐츠

- 기본 표면에는 약한 곡률이 있다.
- 렌즈는 활성선 근처에 기준을 두고 가로·세로 선 간격을 확대한다. 중심이 포인터와 함께 멀어지면서 원래 영역이 다시 축소되는 방식은 사용하지 않는다.
- 확대율은 당김 거리에 따라 계속 증가하다 완만하게 포화된다. 더 길게 당겼다는 이유로 줄어들지 않는다.
- 렌즈, 경계, 꼭짓점을 모두 같은 CSS 픽셀 좌표계에서 계산한다. SVG 전체에 CSS 확대를 중복 적용하지 않아 꼭짓점이 커서에서 벗어나지 않는다.
- 패널은 위쪽 경계와 아래쪽 당김 경계 사이를 SVG `clipPath`로 연다. 양쪽 가장자리도 두 경계를 이어 빈틈이 생기지 않는다.
- 문구는 `안녕하세요`, `이지원입니다`, `잘부탁드립니다` 세 가지이며 각각 한 줄로 표시한다. 첫 번째 겹의 칸은 위에서 아래로 `안녕하세요` → 안쪽 선 표면 → `잘부탁드립니다`를 반복한다. 안쪽 두 번째 겹의 모든 칸에는 `이지원입니다`만 넣는다. 문구는 칸 위치와 겹에 고정되어 있으므로 바깥 칸을 반복해서 당겨도 이름이 먼저 나타나지 않는다.
- 색은 문구 배치와 독립적이다. 선이 새로 활성화될 때마다 패널은 빨강 → 애시드 옐로 → 코발트 블루 → 더스티 라일락 → 세이지 민트 순으로 순환한다. 빨강·블루에는 크림색, 나머지에는 어두운 글자를 사용한다. 줄 사이에서 아직 선을 만나지 않은 입력은 순서를 넘기지 않으며, 당김·복원 중에는 선택된 색 조합을 유지한다.
- 첫 번째 겹의 문자는 열린 틈의 중간점이 아니라 확대되는 원래 표면에 붙어 있다. 길게 당겨도 문자가 아래로 계속 따라 내려가지 않으며, 가로 확대도 유지한다.
- 긴 한국어 문구가 화면 옆으로 잘리지 않도록 첫 번째 겹에도 실제 폰트 치수를 이용한 화면 크기 제한을 적용한다. 기본값에서는 화면 가장자리와 최소 12 CSS px를 띄운다. 첫 번째 겹의 열림 마스크는 그대로 두어 당기는 과정에서 문구가 드러나는 동작을 유지한다.
- 문자의 가로 중심은 항상 화면 중앙이다. 텍스트용 확대 계산도 화면 중앙을 기준으로 한다. 첫 번째 겹은 포인터만 좌우로 움직였을 때 위치와 크기가 변하지 않는다. 두 번째 겹은 가로 중심을 유지하면서 실제로 보이는 공간에 맞춰 크기와 세로 위치만 보정한다.
- 기존 영상 추출 텍스처를 표면 전체에 공유한다. 텍스처에만 적용되는 CSS 확대는 선의 입력 좌표에 영향을 주지 않는다.
- 질감은 384×360 CSS px 타일로 표시한다. 원본의 미세 요철, 불규칙한 밝은 알갱이, 약한 RGB 노이즈를 `surface-relief@1x/2x/3x.webp`에 미리 계산해 둔다. 규칙적인 직조 무늬만 남기지 않고, 검은 바탕에서도 드문 밝은 점들이 눈에 들어오도록 만든다. 평균 밝기를 전체적으로 올리는 대신 밝은 꼬리가 긴 입자 분포를 사용한다.
- 요철을 추출하는 주변 영역과 노이즈 입자 크기는 CSS px 기준이다. 고밀도 이미지에서 커널만 상대적으로 작아지거나 노이즈가 서브픽셀로 축소되어 사라지지 않게 한다. 난수는 좌표에 고정되므로 재생성할 때 같은 결과가 나오며, 실행 중 깜빡이는 노이즈 애니메이션은 없다.
- 기본 요철의 `multiply`·`screen` 결과와 추가 노이즈를 일반 알파 이미지 한 장에 합친다. 검은 바탕의 밝은 입자를 살리되 글자를 검은 구멍으로 훼손하지 않도록 투과율을 유지한다. 실제 높이 변형이 아니라 명암으로 요철을 표현하며, 실행 중에는 전체 화면 필터나 별도 블렌딩 패스를 사용하지 않는다.

## 렌더링 비용

- 포인터 이벤트는 입력 상태만 갱신하고 렌더링을 예약한다. 같은 프레임에 여러 이벤트가 와도 `frame-loop.ts`가 SVG 갱신을 한 번으로 합친다.
- 추종이나 복원 중에만 다음 프레임을 예약하고, 움직임이 끝나면 멈춘다. 다시 입력하면 즉시 깨우되 대기 시간을 물리 적분에 포함하지 않는다. 놓을 때 퍼지는 파동은 사용하지 않는다.
- 중첩 표면은 열린 경로에 필요한 것만 생성한다. 각 표면은 변경 여부를 저장하므로 안쪽을 당겨도 고정된 바깥 표면의 path를 매 프레임 다시 계산하지 않는다. 모두 하나의 프레임 루프와 질감 한 장을 공유하며, 겹을 닫으면 해당 하위 표면과 `clipPath`를 제거한다.
- 문구의 실제 폰트 폭과 전체 높이는 선이 활성화될 때 한 번만 `getBBox()`로 측정해 글자 크기 1 기준으로 저장한다. 이후 프레임은 저장된 치수와 이미 계산된 열림 경계만 사용하며, DOM 크기를 다시 읽거나 별도의 애니메이션 루프를 만들지 않는다.
- 질감 확대는 독립된 `surface-grain` 요소의 transform만 바꾼다. 부모의 상속 CSS 변수를 매번 바꿔 SVG 전체의 스타일을 무효화하지 않는다.
- 텍스처는 낮은 알파에 맞춰 RGB를 작은 단계로 양자화한 뒤 무손실 WebP로 저장하고, 화면 밀도에 맞는 파일 하나만 선택한다. 자산을 다시 만들 때만 ffmpeg가 필요하다. `pnpm generate:line-pull-texture`로 재생성하며 일반 개발 서버·빌드는 저장된 파일을 바로 사용한다.

## 중첩 칸

- 첫 번째 겹은 세 칸마다 한 칸이 문구 대신 비슷한 선 표면을 담는다. 칸의 종류는 위치에 고정되어 있고 클릭 횟수로 바뀌지 않는다. `MAX_LAYERS = 2`로 바깥 표면과 안쪽 표면을 합해 최대 두 겹만 생성한다. 첫 번째 겹을 열고 안쪽 선을 다시 당겨야 `이지원입니다`가 나타나며, 세 번째 선 표면은 만들지 않는다.
- 안쪽 선 간격은 한 단계마다 바깥 간격의 86%이며, 최소 32 CSS px를 유지한다. 각 표면의 줄 위상은 그것을 연 선에 고정된다. 색은 기존 다섯 조합을 순환하며, 안쪽을 열어도 이미 열어 둔 바깥 겹의 색은 바뀌지 않는다.
- 안쪽 줄을 다시 잡으려면 바깥 틈이 열려 있어야 한다. 첫 번째 겹의 중첩 칸은 안쪽 선 두 줄 이상을 조작할 공간이 보일 만큼 열고 정상적으로 놓으면 열린 상태를 유지한다. 정확한 기준은 안쪽 선 간격의 2.2배이며, 화면 밖이나 상위 겹에 가려진 높이는 제외한다. 작게 당기거나 입력이 취소되면 기존처럼 복원한다.
- 두 번째 겹에서 선을 활성화한 뒤 정상적으로 놓으면 첫 번째 겹도 같은 프레임에 복원을 시작한다. 현재 당긴 위치에서 각자의 원래 위치로 돌아간다. 줄 사이에서 선을 만나지 않고 놓거나 입력이 취소된 경우에는 첫 번째 겹을 유지한다. 복원 중 새 입력도 즉시 받는다.
- 열린 면 안의 줄을 다시 누르거나 줄 사이에서 시작해 첫 선을 교차하면 그 표면만 당긴다. 각 겹의 당김 높이에 고정 제한은 없지만, 실제 보이는 내용은 모든 바깥 틈에 의해 잘린다. 중첩 SVG 그룹을 부모의 실제 열림 `clipPath` 안에 넣어 꺾인 가장자리 밖으로 새어 나오지 않게 한다.
- 두 번째 겹의 문구는 화면 전체 크기를 그대로 쓰지 않는다. `copy-fit.ts`가 두 겹의 실제 열린 영역과 화면 안에 글자 사각형 전체가 들어가는 크기를 찾는다. 폭이 넓어질수록 꺾인 아래 경계가 높아지는 점도 반영하며, 글자 양 끝뿐 아니라 그 사이 경계의 꺾임과 곡률도 검사한다. 기본 선 두께에서는 경계와 글자 사이에 12 CSS px의 여유를 둔다. 세로 위치는 기존 배치에 가장 가까운 안전한 위치를 사용한다. 아직 중앙에 열린 공간이 없으면 문구를 표시하지 않으며, 공간이 생기면 그 안에 맞춰 드러낸다.
- 입력도 모든 부모의 열린 영역 안에서만 받는다. 경계에 가려진 선은 직접 잡기와 교차 검사에서 제외하며, 한 곡선의 첫 교점이 가려졌더라도 나중 교점이 보이면 그 교점을 검사한다.
- 틈 밖을 누르면 해당 바깥 표면에서 다시 시작한다. 화면에는 닫기 버튼을 두지 않는다. `Escape`는 열린 첫 겹을 닫고, 드래그 중이면 우선 현재 드래그만 취소한다. 리사이즈는 전체를 초기화한다.
- `prefers-reduced-motion`에서도 첫 번째 중첩 칸을 열어 유지할 수 있다. 추종·복원 애니메이션만 생략하며, 같은 프레임 안에 이동과 놓기가 들어와도 현재 기하를 기준으로 유지 여부를 판단한다. 두 번째 겹을 놓으면 두 겹 모두 즉시 닫는다.

## 복원과 예외 처리

일반 문구 칸이나 충분히 열리지 않은 중첩 칸은 놓으면 감쇠 스프링으로 **해당 X에서의 원래 곡선 높이**까지 복원한다. 느린 프레임에서는 작은 시간 간격으로 나눠 계산하고, 원래 선에 도달하면 종료해 반대쪽 틈이 다시 열리지 않게 한다. `prefers-reduced-motion`에서는 지연 추종과 복원 애니메이션 없이 즉시 반응한다.

`pointercancel`, `lostpointercapture`, 창 포커스 해제는 복원으로 이어진다. 캡처 해제 전에 복원 상태를 설정해 이벤트 중복이 복원 속도를 초기화하지 않는다. 리사이즈는 현재 입력을 즉시 종료하고 필요한 선을 화면 위아래 여유분까지 다시 만든다.

## 검증

Node.js 22.6 이상에서 `node --experimental-strip-types --test pages/line-pull/*.test.mjs`로 지오메트리·텍스트 배치, 두 줄 두께를 유지하는 맞닿음, 중첩 칸 배치·두 겹 제한·실제 열린 영역의 입력 및 유지 조건·상위 겹 동시 복원, 안쪽 문구 전체의 영역 내 배치와 위쪽 당김·모바일·꺼진 영역 처리, 색 조합과 순환, 중복 프레임 방지·대기 후 재개, 기본 질감 합성, 검정 위의 노이즈 대비와 밝은 입자, 고밀도 이미지의 입자 크기 유지를 검사한다. `pnpm typecheck`에 이 페이지를 포함한다.

렌더링은 기존 Chrome에서 레퍼런스와 같은 720×1280 크기로 비교한다. 줄 사이의 짧은 이동, 첫 교차, 짧고 긴 당김, 위쪽 당김, 화면 가장자리, 복원 중 재입력을 확인한다. 실제 드래그의 놓기 직전 프레임을 비교하며 복원 중 프레임을 당김 상태로 오인하지 않는다.

디버그 파라미터는 `?debug`에서 lil-gui로 조절한다.
